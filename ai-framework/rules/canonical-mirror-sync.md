# Rule: every canonical-file edit ships its Cursor byte-copy regen in the same commit

## Why this rule exists

The bundle has two mirror kinds and only one is self-healing:

- **Codex and OpenCode mirrors** are pointer stubs (a small YAML header that says "Load
  `.claude/agents/<name>.md` and follow it exactly"). They inherit every canonical edit
  automatically; no action needed.
- **Cursor mirrors** are generated byte copies of the canonical file. Every canonical edit
  is a **two-file edit** — the canonical and the Cursor mirror — and no step in the edit
  path says so. The byte-identity test in `skill-defaults.test.mts` ("every vendor mirror of
  a skill or agent either points at the canonical file or is byte-identical to it") will
  fail the moment the canonical and the Cursor mirror drift.

This rule has surfaced in 4 distinct pitches (`unified-toon-config`, `agent-model-sweep` Bet 1
and Bet 2, `upstream-project-drift`, `_parked/restore-vendor-adapters`) and one prior
incident (`fix-orca-dispatch-resume-gate`). The original incident was marked `resolved`, but
the class recurs.

## The rule

When a commit edits any of these canonical files:

- `.claude/agents/*.md`
- `.claude/skills/*/SKILL.md`

The **same commit** MUST also refresh the corresponding Cursor byte-copy mirrors:

- `.cursor/agents/<name>.md` (for each canonical agent edited)
- `.cursor/skills/<name>/SKILL.md` (for each canonical skill edited)

The refresh step is:

```sh
node ai-framework/scripts/skill-vendors.mts cursor-mirrors --root .
# Read the report; for every entry under "differs", manually copy the canonical over:
#   cp .claude/agents/<name>.md .cursor/agents/<name>.md
#   cp .claude/skills/<name>/SKILL.md .cursor/skills/<name>/SKILL.md
```

`cursor-mirrors --apply` only creates **missing** mirrors; it does NOT overwrite differing ones.
Manual `cp` is the refresh path.

## Verification

Before committing:

```sh
# 1. Cursor mirrors byte-identical
for f in .claude/agents/*.md; do cmp -s "$f" "${f/.claude/.cursor}" || exit 1; done
for d in .claude/skills/*/SKILL.md; do cmp -s "$d" "${d/.claude/.cursor}" || exit 1; done

# 2. skill-defaults.test.mts byte-identity test passes
node --experimental-strip-types --disable-warning=ExperimentalWarning \
  --test ai-framework/scripts/skill-defaults.test.mts
```

The test failure message names the stale file directly (e.g.
`.cursor/agents/code-reviewer.md is stale — run skill-vendors.mts cursor-mirrors and refresh
it`).

## When this rule does NOT apply

- Editing Codex or OpenCode mirrors (they are pointer stubs; inherit automatically).
- Editing `.opencode/opencode.json` (not in any mirror tree; `FLAGGED_FILES` in
  `bundle-sync`).
- Editing `.codex/agents/*.toml` (mirror, but not a byte copy of the canonical — see the
  `codex-toml-shape` rule once it exists; for now, verify the toml still loads via the
  Codex adapter contract).
- Editing the Cursor mirror itself (no canonical to refresh).

## Exemptions

- None at present. If a future case genuinely cannot honor the rule (e.g. the mirror tree
  is removed entirely), document the exception in the pitch's `deviations.md` and name
  the followup that closes the gap.

## Failure mode this prevents

A byte-identity assertion that fires far from the edit is a mirror problem until proven
otherwise. Read the assertion message before the diff it prints. The `skill-defaults.test.mts`
failure surfaces as a wall of `deepEqual` output from the full `scripts/*.test.mts` run,
several files away from the change that caused it. Catching it at commit time (via the two
verification commands above) keeps the diff small and the cause obvious.
