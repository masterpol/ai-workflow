## Scope and eligibility

The epic was decomposed into compaction-index and compaction-removal, each shaped as at most fifteen files/1,500 lines/one week including mirrors/tests, then C1 (nine estimated paths, 700–950 lines) followed by C2 (four estimated paths, 450–600 lines). Shared schema, playbook and destructive invariants made sequential work appropriate. Registration depended on shipped installation 2.4.0: native entry points, vendor contract and Cursor mirror machinery were reused rather than rebuilt. C1 delivered pitch-compress inventory/ledger/commit-ledger/write-done-work, the generated done-work scaffold and setup-validator check. C2 delivered archive/verify/remove/restore/recover with reused transaction/recovery functions and real process-kill tests.

The original pitch asked incremental inventory of current and archived work; the concrete plan narrowed scanning to working pitch directories, explicitly excluding _templates, _archive and _parked. Only a shipped working directory with SHIPPED.md is a deletion candidate. No SHIPPED, checkpoint or open hill scopes preserve work with an explicit reason. Active, parked, undecided and unresolved lifecycle states are not implicitly resolved by a request to delete everything. A missing or emptied directory already recorded in done-work is compacted. A malformed non-kebab directory must be preserved with a reason rather than crash the inventory and hide other pitches.

The narrow approved maintenance exception applies only to .project/pitches/<slug> for an eligible shipped pitch. It does not authorize rewriting the pre-existing _archive lifecycle tree, design, run records or non-shipped pitches. No application implementation or La Salle infrastructure decision, silent customization overwrite, automatic historical deletion, invented savings or secrets belonged to the delivery. No installation/deletion occurred during shaping/planning. No real checkout pitch was archived/deleted during this tool's build; temporary fixture pitches were archived, deleted and restored. The later narrative's unqualified nothing-deleted-during-build wording needs this distinction.

## Preservation and deletion contract

Read substantive source content and extract decisions, negative constraints, patterns, lessons, outcomes, evidence, requirements and unresolved followups into durable appropriate records. A compact summary alone is not losslessness proof. Extraction quality remains an agent/human semantic judgment; the script validates mechanical completeness and destinations, not meaning. Knowledge records require real IDs, tags and related links; graph validation/schema disagreements block deletion. Status/cross-references must be reconciled before removal, and concurrent edits invalidate previews.

The historical ledger enumerates every level-two SHIPPED heading, pitch no-go/rabbit-hole entries, every audit-cycle file and nonempty deviations/log entries. Genuinely empty constrained sections are excluded. The author maps every required source to a destination or a reasoned gap. commit-ledger rejects missing/unknown/duplicate sources, invalid destinations and referenced knowledge that fails graphify check. Kept destinations must be real nonempty files, realpath-resolved inside the project and outside the pitch being deleted; empty files, directories, external paths and symlinks resolving back into doomed content cannot prove preservation. The v1 numeric extraction ratio was extracted sections divided by required sections; exceptions need explicit named human acceptance, not self-approval by the author.

Every mutating step requires --apply and an approved specific preview. Before deletion, write and verify an immutable recovery copy outside the entire pitch tree: .project/compaction/archives/<slug>-<timestamp>, every source file plus manifest of relative paths/SHA-256 and a checksum of that manifest. The plan's illustrative directory used YYYY-MM-DD; audit lookup validation names the actual full timestamp shape, including time and milliseconds. verify checks contents, checksum, safe manifest-relative paths and exact slug. The archive is retained even if later reporting fails.

remove re-hashes both content and file set against that archive immediately before deletion; changed, added or removed source files are conflicts. It independently re-reads and validates the committed ledger, refusing wrong slug, malformed/hand-placed ledger or any unaccepted gap. Each gap is explicitly accepted through repeatable commit-ledger --accept-gap SECTION=REASON, recorded and rechecked at the destructive step. A bare coverage===1 restriction was rejected because it would prohibit legitimate named human exceptions. Archive, ledger completeness/acceptance, unchanged source and human gate all apply; none substitutes for another.

Deletion uses delete-only transaction operations and deliberately leaves the emptied pitch directory. Already-removed recognizes absent or empty, making reruns true no-ops. restore first verifies the archive, validates containment before each write, recreates exact original bytes, supports an alternate --to inspection directory and refuses a nonempty destination without --force. The wording existing directory in the plan is more restrictive than evidence's actual nonempty-destination refusal; preserve that distinction rather than assert empty directories always fail.

## Shared machinery and generated context

The design reused skill-registry transact/recover/resolveFile/snapshot/digest/json, generic over roots/state rather than calling its skill-specific context helper. The compaction context uses a canonical target root and independent .project/compaction lock/journal state, avoiding collision with .project/skills. Transactions provide verified backups, interruption recovery and hash revalidation. Pending-transaction checks live inside archive/remove/restore themselves, not merely CLI dispatch, so direct imports cannot bypass protection. Reuse was based on inspected signatures and the installation audit, then checked with the prior 111-test skill surface.

The historical done-work writer generated one level-two slug/shipped-date section with short summary, knowledge links, recovery pointer and original run pointer. Same-content rerun is a no-op; a changed rerun replaces only that slug and never disturbs other sections. done-work was generated/read-only to downstream state reporting, not a hand-maintained competing graph. Graph/index stayed generated by graphify; compaction never copied them as its own authority. Instance compaction state and narrative stayed outside bundle-sync roots; global skill state was irrelevant and untouched.

Native discovery used canonical Claude skill, Codex/OpenCode entry points and a scripted Cursor mirror. The project vendor set and missing-host limits were inherited from installation/defaults; absence of an executable never justified missing configured adapters. Mode/resource/override behavior and unsupported runtime measurements had to stay explicit. This delivery reused the established native-skill mirror contract without calling discoverVendors or adding per-installed-skill wrappers. No fresh real-host invocation matrix is recorded in these compaction evidence files; structural checks are not a new runtime certification.

## Audit failures, fixes and confidence

Only code-reviewer completed the four-role audit. Security, test coverage and cross-pitch reviewers failed mid-run with provider HTTP429 session limits, resetting 11:10 pm America/Bogota. The author selected and ran the highest-risk attack scenarios directly instead. This was not independent security/coverage review, and no cross-pitch check completed at all. Audit recommended redispatch before ship; SHIPPED records the user chose to ship without waiting and queued independent re-review. No open findings from checks that ran is not a clean independent fan-out.

Four must-fix defects were reproduced before fixes. Three came from the main-thread security pass, one from code review:

1. Bare slug-plus-hyphen archive-prefix lookup for foo selected foo-bar's archive. The fix anchored exact timestamp shape and checked manifest slug, preventing verify/remove/restore crossing entities. The [prefix issue](../../knowledge/issues/bare-prefix-match-crosses-entities.md) records why a one-entity fixture and 100% coverage missed it: legal separators inside identifiers need shared-prefix adversarial examples and stored identity checks.
2. restore trusted an unverified/tamperable archive and unsafe ../ manifest keys, with a live proof writing outside destination. It now requires successful verification, safe relative paths and containment at every write.
3. commit-ledger accepted a destination inside the directory about to be deleted, or empty/non-file/outside-project destination. A live coverage-one proof preserved nothing. It now verifies real, nonempty, surviving in-project files through realpath.
4. C2's deviation replaced the plan's explicit per-gap human acceptance with merely a ledger exists, reasoning commitLedger already guaranteed accounting. An all-gap coverage-zero ledger then passed remove and deleted all files. This routine-looking simplification was itself the safety bug. Audit superseded it with independent explicit gap acceptance and destructive-step revalidation, including hostile hand-placed artifacts. The reviewer's suggested unconditional coverage-one fix was rejected because it contradicted the plan's legitimate exception contract.

Two should-fix defects were also closed: inventory throwing Invalid pitch slug on non-kebab names hid every other pitch (now preserved-with-reason), and an unused resolveFile import. Five live exploit scenarios were rerun and blocked after fixes. Final pitch suites reported 40/40 with 100% line/branch/function, full ten-file skill surface 151/151, doctor zero failures, validator READY/nineteen checks and graph CLEAN. The earlier 17/31 totals precede audit additions; they are not conflicting final totals. Coverage remains the author's measurement, not the failed coverage reviewer's attestation.

The [gate lesson](../../knowledge/patterns/a-gate-must-not-trust-its-own-author.md) preserves the durable rules: separate claim from independent acceptance; recheck at the destructive function; ensure evidence survives the action; test adversarial artifacts directly. A deviation relaxing safety needs explicit approval rather than routine logging. The source's claim of complete numeric coverage did not prevent concrete live exploits.
