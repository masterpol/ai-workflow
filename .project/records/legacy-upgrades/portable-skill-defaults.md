## D2 attribution and compression guard

Token event mode is an optional plain string for attribution only; no cost/savings inference/schema bump. It reads enabled/default state best-effort under try/catch returning null on failure, lazily reading catalog default rather than hand-duplicating full; it avoids importing the unrelated registry dependency. No mode file or no caveman key gives null. Configured key without default gives bundle full, explicit default gives that mode, enabled:false gives off. There is no phase/invocation context on completion events, so neither tier can be attributed; phase-aware resolution belongs exclusively to resolveMode. Plan language about null when caveman is not installed does not establish a registry-read installation check: cached implementation evidence describes mode-file/key presence. A report saying active mode must be read within this narrower historical contract.

Dedup remains by record.id/recentEventKeys, excluding mode: a replay after mode changed is rejected as duplicate and leaves the original snapshot mode intact. It does not sum overlapping session/request measurements or manufacture unavailable usage.

canCompress returns allowed/reason and does not run compression. Historical protected targets are pitches/_archive, pitches, design and knowledge, with archive checked before its parent to preserve distinct reasons. Refusals also cover nonexistent, non-string, empty and glob/non-exact targets; empty has its own reason. Ordinary in-root exact relative/absolute files may pass. Final audit strengthens realpath/lowercase comparisons and outside-root refusal. Upstream invocation remains explicit human approval with backups/invariants; this readiness guard is consulted before approval, not a replacement. Python availability is a boolean, never a thrown failure and never proof of API access.

Initial D2 evidence: twenty-two tests (ten token cases, including six new plus four existing, and twelve guard cases), all pass; guard-only coverage 94.03% lines/90% branches/100% functions. Python-present branch alone was exercised live then. Token-consumption's older CLI/lock-contention coverage gaps were explicitly outside the final new-script coverage include list. D2 left doctor and integration doc edits to coordinator per worker task boundary; coordinator later added doctor syntax coverage. No external skill was installed/invoked.

## Audit findings and closure

Parallel code/security/test/conflict review ran once; UI/i18n/eval did not apply without UI/translations/AI-prompt scope. Security found two must-fix guard bypasses: an allowed-location symlink into protected pitches passed raw lexical comparison; uppercase .PROJECT/PITCHES passed case-sensitive comparison on the observed case-insensitive macOS filesystem. Both were reproduced against actual exports before and after fixes. Resolve existing ancestors with realpath before comparison, anchor against real project root, refuse outside-root resolution and lowercase normalized relative path before protected-prefix matching. Lowercasing may over-protect a case-sensitive filesystem; no weakened protected check is claimed. This is the [protected-path lesson](../../knowledge/patterns/resolve-before-matching-a-protected-path-allowlist.md).

Third must-fix: D1 manually demonstrated doctor refusal but lacked its explicitly required automated proof. A real-bundle-copy clean-then-corrupted-catalog test now asserts failure with specific check/detail. Two should-fix were closed: modes readers only lstat-checked the leaf and missed symlinked ancestor directories, fixed by real-root confinement in both loadModes/currentCavemanMode; pythonAvailable lacked the sibling probes' five-second timeout, now added. The timeout finding table says confirmed by code reading; surrounding audit/log prose claims all four security findings had before/after live PoCs. Preserve that evidence-granularity discrepancy instead of inventing a timeout execution transcript.

Code reviewer found no inconsistency against skill-sync/skill-vendors precedent. Conflict review found no real conflict with district-multisite-foundation, pitch-compaction or project-state-report; changes were additive. Audit closed after fixes with zero open findings and no redispatch. This consolidation does not relabel that historical review process as a new independent audit.
