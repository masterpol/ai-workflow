## Scope and contract

The problem was missing Codex coordinator startup, accidental use of the CLI's default Claude coordinator, and readiness without a bound Run. The approved big-batch scope was one coherent S1, nine implementation files, estimated 700–900 lines with a hard cap of 1,500 (pitch appetite allowed at most 15 files). Hook/test/registration belonged to Claude; doctor/test to OpenCode; entry mirrors and integration docs to the coordinator. OpenCode's configured model was used because fast-profile availability was not independently verified. The implementation files were the Codex hooks registration, new adapter and test, AGENTS.md/CLAUDE.md, harnesses/orca-vendors integration docs and workflow-doctor plus its test. Release history, records and generated graph were separate artifacts.

The adapter receives at most 64 KiB JSON on stdin and handles UserPromptSubmit. It matches only a leading slash or dollar workflow name followed by whitespace/end, covering all twelve supported phases; quoted examples, prefixes, prose, unrelated skills and embedded commands pass through. Arguments after the name, including newlines, stay unchanged; quoted or escaped bypass text stays data. Vendor is hard-coded Codex, never payload-selected. Root comes from the trusted registration's explicit absolute usable --root and must locate both the adapter and policy; payload cwd and other vendors' root variables cannot redirect it. Direct entry retains runDirect. The POSIX registration pins Node with compatibility flags and preserves SubagentStop metrics.

Once registration bootstrap succeeds, off is silent before input parsing/decision import and policy discovery; worker is silent; bypassed/ready add UserPromptSubmit additionalContext; blocked prints only a safe reason and exits 2. No Run or worker is created by the hook. Script deadline is five seconds, decision budget four seconds or smaller remaining time, host timeout eight seconds; a timer and post-synchronous-probe elapsed check both fail closed. Hung input/probes, bad matching input, import and internal decision failures block without leaking raw prompt/errors. Worker suppression reuses observed Orca terminal membership; no native Codex subagent marker was invented.

Before every coordinator phase, including ordinary conversation or unavailable/untrusted hooks, entry instructions require fresh start with explicit vendor Codex and untouched args-text. Ready permits preparation: inspect run-current with the same executable, create only an absent Run, verify coordinator/objective before reuse and ask before replacing an unrelated binding. Dispatch identifies coordinator Codex and a configured alternate vendor. Collect the attempt's own worker_done, inspect shared edits and rerun exits, release exact settled workers and acknowledge deliveries. Preserve unknown-liveness ownership until recovery proof.

No-gos were OpenCode/Cursor adapters, canonical twelve-skill rollout, 43-test migration, global configuration, trust bypass, local policy, launch/reconciliation guard changes, historical rewrites and application repositories. The Codex handoff remained dated input; AGENTS.md and CLAUDE.md remained byte-identical. No commit or deployment was requested/performed.

The critique accepted retry, shared-attribution and raw-argument lessons; strict parsing, separate activation evidence and stalled-probe checks; a bounded doctor scope and exact mirrors. Run binding was resolved before bet. The original launch receipts were not preserved: recovery used observed run:null plus installed Orca 1.4.222 prelaunch control flow. The official hook contract was consulted on October 8. Build corrected FixtureFile typing, changed failed Git bootstrap from exit 1 to fixed-reason blocking exit 2, and notified doctor ownership through the Dispatch inbox. Later doctor integration required a command handler, runner flags, eight-second timeout and consistent Git-derived script/root; malformed object/JSON and handler/flag/root/timeout variants were added without changing runtime APIs.
