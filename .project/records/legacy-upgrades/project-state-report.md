## Report contract and authorities

Facts are value/status/evidence/note records; status is observed, proposed, stale, unavailable or unconfigured. The report describes product/README/architecture/technology, checked-in database/schema/migration evidence, patterns/decisions and graph freshness, active/shipped/preserved/compacted pitches and hills, registry skills/enabled state/modes/phases/runtime readiness, workflow version/sync provenance, and token completeness/freshness. ## Theme, rendering and write decisions

T2 discovers bounded project CSS/config sources (up to 200 files, 256 KB each), skipping dependency/git/metrics trees. It supports shadcn custom properties and Tailwind v4 theme aliases, including background/foreground/primary/muted/border/radius/fonts. Values are parsed and re-emitted through strict hex/rgb/hsl/length/font grammar; reject URL/expression, separators/braces/markup and quotes, rather than copying CSS. Uncomputable formats such as oklch and text contrast below 4.5:1 fall back with a reason. Both documented light/dark fallback modes are contrast-tested.

The plan's per-pair fallback was corrected: shared tokens require text/accent/subdued groups, then whole-mode fallback if assembled mode still fails. Border/background was deliberately not added as a 3:1 contrast pair: normal shadcn borders around 1.3:1 would reject almost every theme. Attention instead uses a 2px dashed foreground outline on muted, a verified contrast combination. Quoted font families and var(--font-x) originally fell back; this user-visible cost was recorded rather than silently sanitized.

Theme source hashes are stored in theme.json, which is only a record. Contrary to planned unchanged-hash reuse, every run recomputes from bounded stylesheets and compares the record to report changed. Hand-edited theme output must not become trusted CSS input. Optional settings.json schema1 themeMode auto/fallback can force fallback and skips discovery. Instance reports/settings stay outside synced directories; twice-applied bundle-sync tests kept settings/theme/state.html unchanged. Only the README scaffold is tracked. Build initially ignored the entire directory, which would omit the README on fresh clones and fail doctor; ignore rules were corrected to reports/* except README. Sync presents the README as a scaffold next step instead of writing it into project data.

Renderer reads state.json from disk after snapshot generation rather than recollecting: that is the actual untrusted-input boundary. Strings are escaped at output; links require project-relative existing evidence whose realpath stays inside the project and pass secret-name checks. Absolute/data/javascript/external/escaping paths render plain text. Self-contained HTML has inline styles, no scripts or external loads, CSP default-src none with unsafe-inline styles, ordered headings, scoped table headers, viewport/mobile/print/prefers-color-scheme rules. Snapshot/theme values are revalidated at render.

Default is preview with zero writes. Apply uses same-directory exclusive wx random temp files then rename; stale temp files never block reruns. This initial report needed single-file atomic replacement, not multi-file transactions. Clock-injected output is deterministic; real reruns compare ignoring generatedAt so unchanged inputs report unchanged. Do not confuse that with arbitrary-clock byte identity.
