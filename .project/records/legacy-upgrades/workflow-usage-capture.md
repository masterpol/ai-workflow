## Scope and contract

Capture is part A2 of the split of the `token-time-report` seed and a prerequisite of the joined report (part B, re-seeded after capture holds data). At bet time the usage state held 2 manual events ever, and nothing called `recordWorkflowEvent`, so the report printed "Automatic capture: unconfigured". The pitch depended on A1 (`workflow-usage-state`, the state it writes into) and on `token-attribution` S6 (exported resolver, phase-start event) and its S3 gate (`Stop` registration). The phase resolver is the one owned by token-attribution and is shared, never copied; capture never reads the token snapshot. Inferred transitions are never gate decisions.

Pushed to plan as risks: the payload spike (does SubagentStart exist, Stop and SessionEnd keys, expansion order, OpenCode `time.created`, latency p95; owner S1, and an absent SubagentStart would make Claude subagent time Unavailable); the dependency surface on token-attribution (owner the coordinator); per-prompt latency and prompt stalls. Pushed to no-go: Codex capture (its UserPromptSubmit is owned by the Orca entry and a test pins exactly one entry), Cursor, gate decisions, must-fix counts and ship counts. Owner chose "split" and "Bet" at the critique gate, sequenced after workflow-usage-state and token-attribution S3/S6. Critique rows folded in: S9 skeptic (capture.dropped with a bounded retry), TT-1 to TT-4 knowledge, X6, X8 and X16 cross-pitch.

## Standing constraints

- Prompt, response, tool-argument and transcript text is never selected or stored; invocation arguments reach only the phase resolver. A marker test scans every file under `.project/metrics` and stderr.
- No emission steps in skill or phase prose; the token snapshot schema, state schema 2 and the lease are unchanged.
- The hook always exits 0 with empty stdout and fixed stderr lines; it never blocks the agent.
- Registrations are exact Node-prefixed commands (`AI_WORKFLOW_RUNNER=node node ...`), never substring-checked, and fail closed when the runner is absent.

## Plan and event mapping

Plan (base ref 633adb3). Scopes: S1 spike (read-only, scratch project, standard model), S2 pure mapper (new `workflow-capture.mts` and its test), S3 hook entry (same two files, after S2, needs A1 and the resolver), S4 Claude wiring (hooks.json, live settings, `migrate.test.mts`), S5 doctor (fast model), S6 OpenCode plugin, S7 docs (one paragraph in harnesses.md), rollout record and release at /ship. Planned file budget was a firm 12 of 15 (pitch records excluded) and about 1150 lines, not the pitch's 8 files and about 700 lines. Not touched by design: `token-consumption.mts` (frozen until token-attribution S10), the A1 state, report and contract files, `.codex/hooks.json`, SETUP.md.

Start conditions were commands: a G1 record with four verdict lines; C-A1 (A1 shipped); C-RES (the exported resolver exists, and token-attribution's plan had no export exit so the coordinator added one); C-WIRE (token-attribution S6 wiring landed and its S3 Stop decision recorded); C-OC (the OpenCode pair not chosen, or its edits landed first).

Why separate groups: `addMissingHooks` in `runtime/migrate.mts` adds a source group only when no instance group with the same event and matcher already runs a workflow script, and never adds a command to an existing group. A capture command appended to token-attribution's phase-start group would never reach an install that already has that group, so every capture registration is its own group, proven by a migration propagation and idempotence test. The live `.claude/settings.json` and `hooks.json` were not byte-identical (different key order, a subset), so identity is checked per capture group by deep-equal plus one two-file commit, never as whole files.

Planned Claude mapping (adapter `workflow-capture.mts --vendor claude`; all events `source: native`, `vendor: claude`; `occurredAt` from the hook process clock read once; `eventId` a deterministic hash so a twice-registered hook dedupes through A1's recent ring):
- SessionStart (source startup, resume or clear; compact sends nothing) gives `session.started`.
- UserPromptSubmit without `agent_id` gives `agent.started` primary with no labels, activity `turn:<prompt_id or session_id>`.
- Stop with `stop_hook_active` not true gives `agent.finished` completed, label-free.
- SubagentStart and SubagentStop give subagent start and finish keyed by `agent_id`.
- UserPromptExpansion (`slash_command`, no `agent_id`, resolver says phase) and PostToolUse matcher Skill give `phase.started` with the resolver's pitch, phase and scope, activity `segment:<session_id>`.
- SessionEnd gives cancelled turn and segment finishes.
Turn, agent and end events never carry labels: A1 stamps labels from the session's open segment at start and a finish matches on its key, so a mid-turn phase change cannot re-derive a turn's scope (critique S8). OpenCode steps (V2 `session.step.*`) map to agent intervals keyed by `assistantMessageID`; a failed step gives outcome `failed`; the planned user-message wait rule depended on G1 and shipped as Unavailable.

A1 contract capture required (checked at G1): A1-1 a finish matches on (vendor, session, activity) and ignores labels; A1-2 a start on an open key closes the old activity; A1-3 a phase start closes the open segment in the same apply; A1-4 the event that closes a wait gap; A1-5 (optional) a two-event single lease call; A1-6 the resolver sentinels `(unattributed)` and `(none)` stay matchable instead of becoming `(other)`; A1-7 how a lease-busy skip reaches `capture.dropped`. A missing item goes back to A1 and is never patched in A2.

Planned exits and rules: a mutant proof per guard; an `any`-free source check; field allow-list tests with `CAPTURE-TEXT-MARKER`; the hook fixed-stderr set; exact `sh` run of the registered command with only Node on PATH; doctor cases for an echoed command, a `bun` command, missing timeout, `timeout: 30`, a trailing `; true` and a duplicate group (absent capture is a warning); a latency re-measure against the S1 budget; the 15-file and 1500-line cap. Risk table additions: a deadline kill mid-write could leave temp files (so the deadline is checked only before an attempt); a subagent payload never yields `phase.started`; `SessionEnd` may be killed at exit, leaving open turns evicted by A1's 6 h TTL; a duplicate registration is deduped by event id and failed by the doctor.

Pitch claims the plan found wrong: the "second command in token-attribution's phase groups" idea (above); template and live byte-consistency; a lease-busy hook cannot write `capture.dropped` (it holds no lease, hence A1-7); pitch, phase and scope from the resolver hold only for phase-start events; the resolver export was missing from token-attribution's plan; today's state would reject or mis-match capture events (`activityKey` included pitch and phase, a repeated start was refused, and `(unattributed)` normalized to the unmatchable `(other)`); the lease already retries (1000 ms in 25 ms steps), so the bounded retry is that wait plus one outer attempt; the OpenCode plugin has V1 (`message.updated`) and V2 (`session.step.*`) entry points; and a 2026-09-24 spike already showed `prompt_id` on SubagentStop.

Parallel dispatch plan: S1 as a read-only dispatch, S2 in an isolated worktree while A1 was built, S3 and S4 on the main thread, S5 and S6 as a parallel wave, S7 last. The build instead ran every scope sequentially on the coordinator checkout with per-scope approval gates (S5 kept S6 unopened and avoided concurrent resources; its new doctor check is 45 lines). Plan-time measurement corrections: commit-message filtering of `git log --grep` also matched the earlier A1 commit body and missed S6's commit, so the cap is measured as `git diff --numstat 868212b -- ':!.project'`.

## Shaping origin and part B

The shaping draft is titled `token-time-report` (2026-10-19, big-batch, part A capture written in full, part B a short note). Problem: the owner could not see how long a pitch, phase or scope took, how much was waiting on them, or how the flow went; nothing recorded it. Seed claims it corrected: an active-time union cannot be computed at render time (the store keeps summed `elapsedMs` and up to 64 pending starts, so it must be folded at ingest); gate pauses cannot be seen from hooks (only the Stop-to-next-prompt gap); an ordered flow trace needs a new bounded ring because the contract forbids a raw journal; effort exists only in the token snapshot's per-vendor efforts dimension (Claude 1415 of 1468 completions carry one, OpenCode 23 of 1432) and token-attribution's planned flows leaf held none; gate decisions and must-fix counts are emitted by nothing; the cache-hit formula only holds where `input` excludes cached tokens, and the snapshot total excludes `cacheRead`, so any per-scope token figure must name its unit; and the seed's "about 9 files" was really 14 for capture alone.

The draft's wider design (state schema 2 with a scope label, active and wait accumulators at four levels, wait coverage counters, per-pitch transitions and a 32-entry trace ring, a bounded sessions map, an LRU pitch fold at cap 50, a computed `automaticCapture` status of unconfigured, observed within 7 days or stale, and an 8 h wait cap) was split off as A1 and reduced in the shipped capture pitch; it is the historical design intent, not shipped scope here. Resolved there: join keys use the token-attribution resolver output with exact equality on three components and sentinels `(other)`, `(unknown)`, `(unattributed)` never joining (K3); unmatched finishes add nothing and count as unmatched; a pending activity older than the 6 h TTL is evicted and counted; wait is a lower bound; inferred forward, repeat and back transitions are kept in their own counters and never written as `gate.decided`.

Critique rulings recorded in the draft: S7 (activity key includes session and agent id; duplicate and reordered events defined), S8 (one clock source per vendor; out-of-order gaps count as unmeasured), S9, TT-1 to TT-6, appetite TT1/TT2 (the part A estimate was near 1500 lines, split into A1 state and report and A2 capture), X2 (`state-deep-evidence` owns record-derived audit and must-fix counts), X3 (token-attribution's S6 resolver is the single owner), X4 (`state.json` owns token totals; the flow report holds per-flow rows), X6 (the S3 gate decides the Stop registration first), X8, X12, X16 and X20 acknowledged, X21 (rename to `workflow-usage-capture` is the owner's call).

Part B (re-seed `token-time-report`, after capture holds data): a new read-only joiner `flow-report.mts` that reads both stores under one lease and writes `.project/metrics/flow-report.{json,md,html}` with a one-line `/state` link; content per pitch, phase and scope: tokens by vendor and effort mix, active time and wait with coverage, transitions and the trace, per-vendor cache-hit ratios, output over input, tokens per scope with the unit named, and tokens per shipped pitch using done-work names for ship evidence. Open for its shaping: record-derived gate and must-fix counts, coordinated with `state-deep-evidence`; about 9 files. The sources do not verify where this part B ownership now lives in a durable file.

## Payload facts

Spike S1 (2026-10-20, Claude Code 2.1.305, OpenCode 2.1.1, Node 24.21.0; key names and types only, scratch settings only). Observed order: SessionStart, UserPromptSubmit, UserPromptExpansion, Stop, SessionEnd. Expansion before submit is "no", so a typed phase command starts its primary turn under the preceding phase (accepted policy: attribute the first turn to the preceding phase, no retroactive change). SessionStart has no `prompt_id`; submit, expansion, Stop and SessionEnd carry it (SessionEnd also `reason`); Stop carries `stop_hook_active` (boolean), `background_tasks` and `session_crons` (arrays) and `effort` (object). Turn identity is `prompt_id` (equality rests on the documented contract, not a recorded comparison; session id is the fallback for older hosts). Star matchers worked for submit, stop and session end; the SessionEnd record was present after a normal exit, while exit behavior for a killed host is unverified. SubagentStart exists in the official reference but was not exercised live, so subagent fields are documentation-based, as is the PostToolUse Skill payload (tools were disabled). OpenCode: user `time.created` unverified, turn boundary unavailable, V1 gives completion time only, and A1 closes a wait gap only on a primary `agent.started` (no user-message kind), so a user message must not be faked into a primary activity.

Gate record at the spike: A1 contract blocked (A1-3 and A1-6 missing, A1-1 and A1-2 partial), resolver export `resolvePhaseContext`, token Stop group present, OpenCode pair not-chosen. The owner approved G1 on 2026-10-20 with the amended contract: primary starts supersede missed turns, duplicate subagent starts stay rejected, eight separate Claude groups, prompt-id turn identity with session fallback, preceding-phase labels before expansion, no OpenCode wait without a verified boundary, a 250 ms p95 budget. Earlier blocked or pending lines in the spike are historical observations, not current gate state.

## Delivered behavior

- The mapper selects only validated identifiers (bounded to 96 characters so prefixed activities fit A1's cap) and canonical labels; turn identity is the prompt id with a session-id fallback; Turn, Stop and end events never consult the resolver; ignored text-field getters are never evaluated; unknown, oversized or wrong-type metadata and invalid clocks emit nothing. It is a 115-line cohesive module (a documented exception to the utility-size guideline); the entry brought it to 193 lines.
- OpenCode V2 steps carry an unknown agent kind so no user-turn wait is implied (the A1 integration test saw two matched intervals, 2000 active ms, no wait or primary turns). V1 messages and unverified boundaries emit nothing. A skill tool call can open a phase through the resolver. The V2 test host now acknowledges an event when the stream requests the next one, so a scratch directory is not deleted between the token write and the capture write; immediately delivered events are removed from the queue to avoid fixture replay.
- SessionEnd writes two cancelled units with distinct event identifiers and still attempts the segment close after a failed turn write. Identical selected metadata with the same clock deduplicates; two independently fired hooks with different clock readings do not, so the one-registration checks stay required.
- CLI: 64 KiB bounded stdin plus a UTF-8 byte check, trusted root and vendor arguments, the real `resolvePhaseContext`, silent stdout, a closed set of fixed stderr lines, exit 0 always. Mapping runs before any metrics operation, so non-phase calls never take a lease or create the metrics directory. `captureWorkflowEvent` is the in-process boundary S6 uses; main accepts only the Claude vendor. A shared 3000 ms monotonic budget is checked before each writer call; A1 keeps its own internal bind retries.
- The A1 dropped counter counts refused write attempts, including a retry-recovered one (one recovered refusal counts 1, two final refusals count 2 at the next successful write), not permanent event loss.
- Wiring: SessionStart, UserPromptSubmit, Stop, SessionEnd, SubagentStart, SubagentStop, UserPromptExpansion and PostToolUse (matcher Skill); others use matcher star; each runs the exact Node-prefixed adapter command with timeout 5 and a description. Existing token and Orca groups are deep-equal to before and capture is appended after them; migration adds all eight once, is idempotent and keeps an existing wrapped capture command; Codex wiring is unchanged. Without Node on PATH the shell exits non-0 and non-2 with empty stdout and unchanged state (the test accepts either "not found" or "No such file" wording).
- Doctor: checks command, type, matcher, timeout and cardinality per registration, warns when capture is absent, fails on an unexpected event; a substring-compare mutant is killed by the echoed-command test.
- S2 evidence: 12 tests, 14 mutants killed (text privacy, label-free Stop, identifier and metadata caps, validations, time guards, subagent isolation), 98.26% lines; one fixture bug (collector clock ahead of earlier intervals) was fixed in the test, not in A1. S3: 25 tests (94 in the combined command), 98.96% lines, four mutants killed (pre-lease phase rejection, two-attempt limit, deadline, input byte guard); a full marked Claude sequence gave four matched finishes, 4000 active ms and 1000 wait ms. S5: 72 tests, six mutants killed. S6: 43 Node and 16 Bun plugin tests, 98.00% plugin lines, six added behavior tests.
