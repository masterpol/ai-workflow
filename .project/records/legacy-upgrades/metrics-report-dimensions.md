## Behavior and schema contract

The user previously saw one vendor table and two numbers because the snapshot did not aggregate useful dimensions. S0 established payload fields, S1 implemented schema v2, S2 split rendering into token-report, S3 wired feeders, and S4 updated docs/doctor and replayed the CLI. Markdown and HTML now open with Usage: most used vendor and model plus an explicit ranking basis, followed by vendor, model, agent, reasoning-effort and skill tables. Missing dimensions show Unreported; absent/nonzero-cost-less pricing shows Unpriced. Missing token usage is unavailable rather than zero. OpenCode completions are assistant messages while Claude/Codex use subagent stops; the separate By Vendor Unit table explains those incompatible units without changing the pinned By Vendor header or Current Completion table/Caveman mode column.

The headline derives vendor totals from model rows, so tokens and completions share dimensions.since. If model rows do not exist it falls back to lifetime vendor completion counts, whose lack of token totals makes the ranking completion-based; the sentence states that basis. A vendor reporting one token outranks one with 500 completions and no reported tokens. Null since says Not yet counted; empty input says No data yet. Overflow is labeled Other (overflow). Blank v2, snapshots without dimensions and prototype-shaped vendor names were tested not to throw.

V1 migrates in place, retaining lifetime totals and adding empty dimension maps plus an ISO since timestamp. No historical records are available to backfill; older collectors cannot read v2 and may blank it on downgrade. Row values are completions, reportedUsageCount, unavailableCount, tokens, costUsd and pricedCount; skill rows hold uses. Models, agents, efforts and skills are nested by vendor in null-prototype maps, including the older vendors map; the renderer never splits compound names. Effort means harness reasoning effort, as the user confirmed on 2026-09-24, rather than fast/standard/deep routing.

Reversible aggregates store whether dimensions were applied and their exact model/agent/effort routing buckets. Reverse uses stored routing, including other, rather than recomputing after a cap changes. Pre-migration current/previous records skip dimension reversal. New dimension arithmetic has no Math.max clamp; over-subtraction must fail loudly, although a pricedCount clamp was retained in the old lifetime-vendor block. Tests cover replay/upgrade, a pre-migration record and apply-then-reverse, including changed caps and other routing, on the collector as it exists on disk.

Skill-use takes its own branch: it never rotates current/previous, increments completion totals, invokes completion applyRecord or changes recentEventKeys. Its own dedup ring holds 50 keys; the completion ring holds 100. Nameless skill events write nothing. Distinct names are capped at 25 per vendor per dimension; reserved __proto__, constructor and prototype route to other. Names are trimmed/truncated to 80 characters and later restricted to ASCII identifier characters (word characters plus period, colon, slash, at-sign, plus and minus). Rejected labels share a counted other bucket. Opaque ids remain machine-readable up to 128 characters, but any id rendered as a human label must pass the identifier check again. HTML escaping and Markdown cell escaping remain required.

## Constraints and bounds

No prompts, responses, tool arguments, skill args or transcripts are stored; only allowed identifiers and numbers. Marker tests place text in skill args, agent prompts and assistant messages through the CLI, hooks and plugin and find zero matches in JSON, Markdown and HTML. No per-run logs or unbounded arrays, no backfill/estimated history, no Cursor collector, no estimated Claude/Codex cost or tokens, unchanged caveman attribution and never-block-the-agent behavior, and ignored local metrics output were explicit no-gos. Time-series trends and a broader dashboard were deferred. Hook paths catch invalid input and exit zero.

Audit bounded cost above 1e6 USD and tokens above 1e12 as unreported; ids at 128 characters; statuses as names; agent model-note keys prefixed agent: to avoid numeric-key eviction; plugin maps capped at 200 sessions. A 2,000-event stress with 9,000-character ids and 60 distinct names produced a 3 KB snapshot. At maximum allowed cost/tokens, 2,000 events produced 4e15 tokens/about 2e9 cost in 6 KB, without NaN/Infinity. Exact integer sums beyond 2^53 remain an acknowledged local-input limit. These historical bounds were later found incomplete by D7, described below.
