## portable-skill-installation — shipped 2026-09-25

Tracked skill installation shipped as bundle 2.4.0 in three sequential scopes: S1 the verified, transactional
installer (`add-skill.js`, `skill-registry.js`, `skill-source.js`, `skill-vendors.js`; exact Git-object

formatting with dual-hash tracking. 63 tests, 100% line coverage on the four `skill-*.js` modules.

unescaping in `skill-source.js`, with regression tests), one deferred (an ancestor-symlink TOCTOU race that
needs a co-resident writer), one note closed by a regression test showing the formatter's `--config` only ever
resolves from the trusted project root. The downstream pitches (defaults, compaction, metrics, state report)
were checked against what was built and all four have since shipped on this registry.

## pitch-compaction — shipped 2026-09-25

Recoverable pitch compaction shipped in two scopes: C1 the `/pitch-compress` skill (all vendors) with
`pitch-compress.js` (`inventory`, `ledger`, `commit-ledger`, `write-done-work`) and the `done-work.md` scaffold;
C2 `pitch-archive.js` (`archive`, `verify`, `remove`, `restore`, `recover`) reusing the audited transaction
machinery, with real SIGKILL interruption tests. 40 tests for the pitch (151 across the skill surface), 100%
line, branch and function coverage.

Confidence caveat kept on purpose: the audit was only partly independent. Only the code-reviewer completed; the
security, coverage and cross-pitch reviewers died on a provider rate limit, so the author ran the highest-risk
attack scenarios directly. That closed four must-fix defects (an archive lookup that crossed between pitches
sharing a slug prefix; `restore` trusting an unverified, tamperable archive; a ledger destination inside the pitch
being deleted; a ledger whose author declared every section a gap passing the deletion gate at coverage 0) and two
should-fix. An independent re-review is a followup, and this tool's first real use is recorded there too.

No-gos held: every mutating step needs `--apply`, deletion needs a verified archive, a complete ledger with each
gap explicitly accepted, an unchanged source, and a human gate; nothing was archived or deleted during the build.
The design is in [[pitch-compaction-gate-and-recovery-design]]; lessons in [[a-gate-must-not-trust-its-own-author]]
and [[bare-prefix-match-crosses-entities]]; constraints in
[[workflow-tooling-pitches-share-standing-no-gos-and-design-answers]]. `project-state-report` reads this file as a
generated, read-only source. No CHANGELOG entry was ever written for the feature itself (only the 2.8.0 hardening entry
mentions `pitch-compress`); see the followup on that.
