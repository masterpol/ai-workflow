# knowledge-historian: workspace-slim + knowledge-distill

Read-only review. Knowledge ids are under `.project/knowledge/`. "Not cited" means missing from that pitch's "Knowledge consulted". No tests or eval cases were run.

| ID | Pitch (slim/distill/both) | Severity (high/medium/low) | Type | Finding | Suggestion |
|----|----|----|----|----|----|
| K1 | slim | high | missed-knowledge | Converting existing archives breaks consumers of their layout. `ai-framework/scripts/pitch-archive.mts` `verify` walks `<archive>/files/`, and `restore` depends on `verify`; `legacy-upgrade.mts:288` also calls `verify`. LAH `.project/done-work.md` has 26 lines naming archive paths. The sampled lines are backtick text, not Markdown links, so a link check (dataset `record-is-linked`) would not see them. Not cited: `issues/live-test-evidence-outlived-its-pitch-path` (inventory test and tool consumers of paths, not just prose links; prove complete bytes before retiring). | Before converting or replacing evidence folders, inventory plain-text paths, scripts and tests. Keep a stable manifest path, and make verify/restore read both formats. Add golden cases for a tool or backtick consumer and for restoring an old-format archive. |
| K2 | both | high | missed-decision | "Not duplicated" recovery changes a recorded deletion contract. `decisions/pitch-compaction-gate-and-recovery-design` (not cited by slim) requires a verified archive plus ledger before deletion and calls recovery "archive (plus git history)". `decisions/compaction-recovery-shares-context-and-trusted-directories` (not cited by either) requires one `.project/compaction` journal and context. Pending journals block new mutations, and path safety assumes cooperating control of ancestors. Slim's apply and distill's removal of originals are both new mutators. | Add a decision that supersedes or narrows the archive requirement. Require both mutators to reuse that transaction context, refuse on pending journals, and test with a real SIGKILL. Cover `issues/hardening-a-shared-reader-made-its-writer-destructive`: trace `restore`, `verify` and `remove` when the shared reader changes. Do not read archive bodies broadly during consumer scans (`issues/verified-cache-review-does-not-authorize-archive-search`). |
| K3 | slim | high | missed-pattern | The Git-as-recovery spike has uncited prior art. `legacy-upgrade.mts` `committedDestinations` already refuses shallow history, uses `--no-replace-objects`, `--literal-pathspecs` and `GIT_NO_LAZY_FETCH`, and hashes blob bytes at `rev:./path`. It finds the introducing commit but does not check reachability from main. Working bytes can differ from blob bytes under eol or filter attributes: climbing-lab reports `text: unset` for `status.md`, so attributes vary between projects (a mismatch was not shown). Current manifests also store file mode. | Reuse this guarded Git runner. Record commit, repo-relative path, blob id, content hash and mode. Refuse when working bytes differ from blob bytes, then add the main-reachability check. Re-check it at restore and fail closed with the commit named. Test CRLF/filter, shallow, replace-ref and LFS or partial-clone cases. |
| K4 | distill | high | missed-knowledge | Removing or merging originals affects ledger bindings, not only links. Of the ledger files, 39 of 40 in LAH, 10 of 10 in RN and 10 of 14 in climbing-lab mention `.project/knowledge/` paths. `pitch-archive.mts` (lines 173-207) requires those destinations to exist before `remove`. `legacy-upgrade.mts` refuses a missing or drifted v1 destination unless drift is explicitly accepted, and that acceptance cannot cover a missing file. `decisions/legacy-upgrade-drift-acceptance-binds-both-versions` (not cited) says applied upgrades need not keep the hash, so the exposure is pending removals and upgrades. Counts of v1-marked files may include preserved siblings; pending state was not checked. | Have `distill` candidates read ledger destinations. Refuse any original bound by a pending ledger or upgrade, or require that campaign to finish first. Alias ids cannot satisfy a file-path check. Add a golden case. |
| K5 | distill | high | missed-pattern | "Old ids stay resolvable (aliases)" does not keep file links valid. `outcome-record.mts` `targetProblem` requires each linked target to be a regular file; the cited deletion issue records the resulting graph refusal. A search found 490 knowledge-path mentions across `.project/records`, `done-work.md`, `ai-framework` and `.claude` (includes test fixtures; not all are live links). `graphify.mts` (lines 255-271) already has reciprocal `supersedes`/`superseded_by` validation, for decisions only. `issues/valid-outcome-records-can-lack-queryable-navigation` (not cited) shows lint-clean links can still be unnavigable. | Prefer a small tombstone file at each old path, extending supersede semantics to all entry types, over graph-only aliases. Assert traversal from each old id and each shipped record to the new entry, not just a clean check. Slim's "entry counts unchanged" proof must define how tombstones and distilled entries count. |
| K6 | slim | medium | scope-evidence | "One short line per entry" will not shrink the index much: `graphify.mts` `renderIndex` already emits one line per entry. The bulk is the Tag Index and Mermaid Graph: about 88 KB of this repo's 116 KB, 45 KB of LAH's 60 KB and 56 KB of RN's 85 KB. `/knowledge-health` reads `index.md` for its inventory, and `setup-validator` and doctor expect the file. `patterns/convert-a-format-only-where-an-agent-loads-the-file-and-measure-it` (not cited) requires naming the reader and measuring the saving. | Retarget the work: remove or split Tag Index and Mermaid (both derivable from `graph.json`), keep path and counts, list each reader as file:line, and set a measured before/after byte target. |
| K7 | distill | medium | missed-knowledge | The independent check needs enforced isolation. `patterns/a-gate-must-not-audit-its-own-instrument` (cited) says build-time self-tests are not independent review. `issues/verified-cache-review-does-not-authorize-archive-search` (not cited) shows a reviewer's broad search crossing its approved sources; its fix used allowlisted isolated copies. `patterns/a-planted-canary-makes-a-reviewer-finding-checkable` (title matched, body not read) is also relevant. The "passing check record" binding alone shows no provenance. | Give the checker a scratch copy with only originals and result, and no draft ledger. Plant at least one deliberately dropped exception it must catch. Bind the check record to both content hashes. If the host cannot isolate, mark the item not-checked and refuse apply. |
| K8 | distill | medium | missed-pattern | `patterns/a-compression-pilot-keeps-failed-candidates-and-defers` (not cited) is the closest earlier lesson: freeze the baseline, apply a no-new-loss rule, keep rejected candidates, and defer instead of tuning until green. Distill blocks a failed item but sets no retry limit, so the author can revise against the checker's questions until it passes. | Freeze the questions per original hash before drafting is revised. Allow a bounded number of retries (for example one), with a fresh checker. Keep rejected drafts and misses as evidence, then defer. Make this the stop rule and add it to `independent-check-fails`. |
