# Eval regression projection: workspace-slim + knowledge-distill

## Gradability summary

**workspace-slim.json** — 6 cases, 4 bound to tests (`report-before-any-change`, `knowledge-and-rules-are-kept`, `content-not-in-git`, `record-is-linked`) and 2 live-only (`unknown-folder`, `followups-triage`). Per `.project/knowledge/patterns/a-golden-dataset-case-counts-only-when-a-named-test-passes.md`, the live-only cases are not gradable as enforced.

**knowledge-distill.json** — 6 cases, 3 bound to tests (`no-statement-lost`, `links-still-resolve`, `independent-check-fails`) and 3 live-only (`similar-but-different`, `unverified-claim`, `promotion`). The live-only cases are not gradable; regressions in condition/exception preservation, unverified-claim handling, and promotion breadth will not be caught by CI.

## Findings

| ID | Pitch | Severity | Type | Finding | Suggestion |
|----|-------|----------|------|---------|------------|
| E1 | slim | high | golden-blind-spot | Two cases are `live-only` (`unknown-folder`, `followups-triage`) and have no named test binding, so any regression in classification or backlog triage will pass silently. `.project/knowledge/patterns/a-golden-dataset-case-counts-only-when-a-named-test-passes.md` says unrun live cases are not passes. | Add scripted test bindings (e.g., stub filesystem fixtures) for the report classifier and backlog sorter, or explicitly mark these cases deferred/not-graded. |
| E2 | slim | high | regression-class | No case exercises the restore-and-compare proof or the main-branch reachability rule for squash merges / shallow clones. The pitch itself pushes this to `/plan` as a risk (`.project/pitches/workspace-slim/pitch.md` lines 75-78), and `.project/knowledge/issues/deleting-a-file-breaks-shipped-outcome-records-that-link-to-it.md` shows deleted files can break links silently. | Add a test-bound case that removes a committed file, makes the commit unreachable, and asserts the proof fails closed instead of recording a recoverable pointer. |
| E3 | slim | medium | golden-blind-spot | `record-is-linked` only checks links from shipped outcome records; it does not cover tracked tests or datasets that open the path. `.project/knowledge/issues/live-test-evidence-outlived-its-pitch-path.md` shows a dataset regression outlived a removed pitch file. | Add a case where a proposed deletion is referenced by a tracked test or dataset and must be refused or the consumer updated before removal. |
| E4 | slim | medium | structural-gap | No golden case covers converting existing byte-copy recovery archives into hash-and-commit records while keeping `pitch-archive restore` exact. The pitch says existing archives can be converted once bytes are proven in Git (`.project/pitches/workspace-slim/pitch.md` lines 51-53, 77). | Add a test-bound case that converts an old byte archive and verifies `restore` returns the exact original bytes. |
| E5 | distill | high | golden-blind-spot | Three cases are `live-only` (`similar-but-different`, `unverified-claim`, `promotion`). Silent loss of conditions, exceptions, or unverified qualifiers will not be caught by CI. `.project/evals/datasets/knowledge-distill.json` cases `similar-but-different`, `unverified-claim`, and `promotion`. | Add automated contract-test variants that extract statements from originals and the condensed result and compare conditions/exceptions/qualifiers. |
| E6 | distill | high | regression-class | `no-statement-lost` only checks that the ledger lists every original section; it does not verify the condensed text preserves conditions or does not overgeneralize. `.project/knowledge/issues/instruction-copies-drift-into-contradictions.md` and `.project/knowledge/patterns/one-owner-per-instruction-topic-guarded-by-contract-tests.md` show rules can silently broaden or contradict without such a check. | Add a test-bound semantic-diff case that asserts every condition/exception in the condensed output is present in the originals and that no new unconditional rule appears. |
| E7 | distill | medium | structural-gap | No case verifies the independent checker is actually isolated from the author's draft ledger. The pitch lists this as a `/plan` risk (`.project/pitches/knowledge-distill/pitch.md` line 65), and `.project/knowledge/patterns/a-gate-must-not-audit-its-own-instrument.md` shows self-audit instruments have the same blind spot they guard against. | Add a case that fails if the checker's input contains the draft ledger, proposed destination, or author hints. |
| E8 | both | medium | structural-gap | The tandem relies on `workspace-slim` recovery for `knowledge-distill` removals, but neither dataset has a cross-pitch case that removes an original via `distill` and restores it via `slim`. `.project/pitches/knowledge-distill/pitch.md` lines 80-83 and `.project/pitches/workspace-slim/pitch.md` lines 100-103. | Add a shared tandem eval binding: after `distill` removes originals, use `slim` recovery to restore them and verify aliases and record links still resolve. |
