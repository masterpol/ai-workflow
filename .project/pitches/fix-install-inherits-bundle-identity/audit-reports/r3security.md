# Security audit of setup-validator

Reviewed the files in the scratch copy against `CHANGE.patch`, the pitch log's “Revision before ship,” and `ai-framework/rules/security.md` §9 and checklist G. The linked `SETUP.md` regression remains open in both the patch and the scratch source. Other findings below distinguish changed behavior from existing gaps in the requested review scope.

## Findings

1. **High / `ai-framework/scripts/setup-validator.mts:164` / §9 guarded reads and bounded input.** The bundle marker uses `deps.fs.readFile` directly and splits all returned text. With a linked `SETUP.md`, the validator can treat a title read through the link as a provenance marker and pass stale `AGENTS.md` and `CLAUDE.md`. A FIFO can block the direct read and an oversized file can be read in full. In an in-memory run of `main` using the expected bundle title behind a symlink, the shared reader separately returned `Guard: Refusing symlink: SETUP.md`. The validator instead recorded `direct read SETUP.md`, followed by `AGENTS.md: project specifics are filled` and `CLAUDE.md: full project mirror is present`, both with status `pass`. Command A below. The regression at `ai-framework/scripts/setup-validator.test.mts:351` asserts the opposite result. Use the quiet guarded reader for the marker so refusal leaves the install check enabled.

2. **High / `ai-framework/scripts/setup-validator.mts:222`, `ai-framework/scripts/setup-validator.mts:257` / §9 execute only bundle code and resolve tooling from a trusted root.** The validator uses the analyzed project's working directory for its children and supplies relative entry paths for both graphify and doctor. Running a trusted validator against a separate project therefore selects the project's copies of those modules. A project-local replacement gains the privileges of the invoking validator and can supply its own validation result. Existing code, now in scope through the output changes. Mocked process dispatch logged `child ai-framework/scripts/workflow-doctor.mts cwd /mock-project` and `child ai-framework/scripts/graphify.mts cwd /mock-project`. The resulting checks both passed on the stub's reports. Command A. No project code was executed for this check. Pin both entry paths to the running bundle, keeping the analyzed project as the data root.

3. **Medium / `ai-framework/scripts/setup-validator.mts:119`, `ai-framework/scripts/setup-validator.mts:243`, `ai-framework/scripts/setup-validator.mts:270`, `ai-framework/scripts/setup-validator.mts:282` / §9 guard reads and directory listings.** Existence fallback, rules counting, and TypeScript discovery use unchecked `readdir`. A linked rules directory is counted and a linked scripts or hook directory can feed outside paths to the parser. TypeScript candidates go to Node's unbounded `readFileSync` in the parse snippet at line 53, or to Bun build, with no file-type, size, or containment check at the validator boundary. A listed FIFO can tie up a parser slot until child timeout. Existing code. Command A showed `rules listing without inspection` and `child /mock-project/.claude/hooks/fixture.ts cwd /mock-project`; the mock logged no leaf inspection. The Node parse snippet was reviewed statically. Actual Bun file and config behavior was unverified.

4. **Medium / `ai-framework/scripts/setup-validator.mts:251`, `ai-framework/scripts/skill-vendors.mts:147`, `ai-framework/scripts/skill-vendors.mts:164`, `ai-framework/scripts/skill-vendors.mts:170`, `ai-framework/scripts/skill-vendors.mts:176` / §9 guard reads and directory listings.** The read-only mirror check still lists canonical directories before verifying the directory path and directly reads both mirror sides. The path resolver checks symlinks in file path components, but the listed entries and final destinations have no regular-file or byte-bound requirement before reading. A FIFO at a canonical agent path can block the validator synchronously. Oversized canonical or mirror files can be read in full. The auxiliary skill registry and vendor reads also bypass the bounded reader at `ai-framework/scripts/skill-registry.mts:104` and `ai-framework/scripts/skill-vendors.mts:41`. Existing read paths. Command B's synthetic FIFO entry reached `unbounded read /mock-project/.claude/agents/note.md`. An injected `AUDIT_STOP` ended that read immediately; no real FIFO was opened.

5. **Medium / `ai-framework/scripts/setup-validator.mts:81`, `ai-framework/scripts/outcome-record.mts:53` / §9 guard project reads.** Ledger and outcome reads check the path, then open it separately. A ledger can grow past its checked size or change type before the async read. The outcome read caps the bytes after opening, but the blocking open can still follow a replacement symlink or wait on a FIFO. Existing code. Command B successfully read the synthetic ledger and record through their respective reader paths. The race is a static finding; no filesystem race was run. For comparison, Command C showed that the shared descriptor reader rejects both an identity mismatch (`changed File changed while opening: AGENTS.md`) and growth (`growth File grew beyond bound: AGENTS.md`).

6. **Medium / `ai-framework/scripts/setup-validator.mts:182`, `ai-framework/scripts/setup-validator.mts:214`, `ai-framework/scripts/entry-import.mts:59` / §9 read through one guarded reader.** Even without concurrent changes, a hard-linked `AGENTS.md` can be read by the import resolver after the direct entry check refuses it. The resolver accepts a regular file with multiple links and decodes through the ordinary filesystem text adapter. That can also admit invalid UTF-8 refused by the direct reader. The overall report still fails on the directly checked entry, but refused bytes can influence the Claude mirror and response-style checks. Command A returned `Guard: Not a plain bounded file: AGENTS.md` and `Hard-link import resolver: import` for the same mocked file. This is a difference in the static read policy, independent of any path race.

7. **Medium / `ai-framework/scripts/setup-validator.mts:157` / §9 linear regex.** The context placeholder expression can retry its unanchored `<[^>]+>` branch at each opening delimiter. A long context file with repeated opening delimiters and no closer can cause repeated suffix scans on the main thread, even with the 1 MiB cap. Existing expression. Command D printed the regex at line 157. The complexity finding is static; no stress input was run and wall time is unverified.

8. **Medium / `ai-framework/scripts/setup-validator.mts:83`, `ai-framework/scripts/setup-validator.mts:97`, `ai-framework/scripts/setup-validator.mts:227`, `ai-framework/scripts/setup-validator.mts:261` / §9 keep raw errors and absolute paths out of output and validate values before rendering.** TypeScript casts do not validate the child reports. A string in place of a numeric count reaches the operator in both plaintext and JSON. Ledger and outcome diagnostics likewise copy arbitrary values from malformed records. `printable` removes C0/C1 characters but retains path text. A malformed record or child response can disclose a path in a log that an operator shares. Command B, using synthetic path markers, emitted:
   - `Workflow doctor: /mock/doctor-note workflow contract failure(s)`
   - `Knowledge graph: graphify validated /mock/graph-note entry(ies)`
   - `Compaction ledgers: 1 invalid: demo (unsupported ledger schemaVersion "/mock/ledger-note"; this tool reads 1 and 2)`
   - `Outcome records: 1 fail the lint: demo (frontmatter slug "/mock/record-note" does not equal the file name stem "demo")`

## Checklist G

| Item | Result |
| --- | --- |
| Refuse symbolic links, special files, outside paths and oversize inputs, including directory listings | Fail. Findings 1 and 3–6. The context, direct entries and status route through the shared reader. Command C accepted a normal file, returned null for missing, and refused symlink, FIFO, oversize, changed identity, growth, and invalid UTF-8. No Unicode normalization expansion was observed in these validator paths. |

| Keep raw errors and absolute paths out of reports | Fail. Finding 8. Checked stdout in both modes by following the shared `record` function and JSON serialization. The fixed messages for child stderr, mirror exceptions and internal exceptions in `main` suppress raw exception text. `entry-import.mts:55` returned a fixed message without the malformed directive in Command A. Config diagnostics at lines 308 and 311 still render parser-provided detail, and the direct runtime bootstrap's stderr path at `ai-framework/scripts/runtime/cli.mts:32` still renders raw exception messages. I did not verify an absolute path through either of those two adjacent paths. |
| Writers refuse unsafe targets and replace atomically | Not applicable. The validator itself only emits to stdout and stderr, passes no `apply` option to mirrors, and requests graphify check mode and doctor JSON mode. The project-relative child dispatch breaks the assumption that those arguments select read-only bundle code. |
| Writer re-inspects and publishes the expected inode | Not applicable. No publish path in the validator. |
| Cleanup checks the published inode and marker | Not applicable. No cleanup or deletion path in the validator. |
| Every publish guard has an injected-hook test | Not applicable. No publish guard in the validator. |

The absent/refused contract in §9 also applies to callers that might write on absence. The validator itself has no such callers. Its quiet read intentionally combines absence and refusal for the advisory entry-file recheck. The primary guarded read reports them separately. Outcome listing can hide a refused directory as “none yet” through `ai-framework/scripts/done-work-index.mts:47`; no write follows that classification here.

## Commands and verification limits

- **A.** `node --experimental-strip-types --disable-warning=ExperimentalWarning --input-type=module` with an inline harness importing `main`, `readProjectText`, and `resolveClaudeEntry`. It supplied synthetic `/mock-project` filesystem results, a same-title symlink marker, stale entry text and a two-link file stat. It captured child arguments and returned synthetic runtime results. Output is quoted in Findings 1–3 and 6 and in checklist G. No project child or filesystem fixture was created by this harness.
- **B.** Same inline Node command, importing `main` and `cursorMirrors`. It supplied a synthetic ledger and shipped record with malformed field values, child reports with nonnumeric counts, and a synthetic FIFO directory entry; it intercepted the attempted mirror byte read. Output is quoted in Findings 4, 5 and 8.

It injected one filesystem response at a time for a small ordinary file, ENOENT, symlink, non-regular file, oversize, changed inode, growth, and invalid UTF-8.
