# Critique: greenfield-kickoff — eval-regression-projector

Source: `.project/pitches/greenfield-kickoff/pitch.md`, `.project/evals/datasets/greenfield-kickoff.json`, and the knowledge entries cited below.

## What the golden cases currently catch

The 7 cases cover the headline behaviors in the pitch's affordances: empty-state detection, purpose-first questioning, stack recommendation, existing-code routing, contradiction detection, secret refusal, definition-to-first-version writing, and session resume. They are all `live-observed`, `executionStatus: specified-not-run`.

## What they do NOT catch

| ID | Severity | Type | Finding | Suggestion |
|----|----------|------|---------|------------|
| E1 | high | golden-blind-spot | **Command-name shadowing is untested.** The pitch explicitly pushes "Is `kickoff` free in each host?" to `/plan` as a risk (`pitch.md:63`), and the repo already lost `/ship` to a Claude Code built-in (`a-workflow-command-can-be-shadowed-by-a-host-built-in.md`). A future host built-in named `/kickoff` would silently break the skill, and none of the 7 cases would fail. Observable by running `/kickoff` in each host; gradable by whether the canonical skill loads. | Add a `host-registration` case (or rename to `project-kickoff` now) and bind it to a test that asserts the command resolves to the workflow's canonical skill in every vendor adapter. |
| E2 | medium | test-binding-gap | **No case is bound to a named passing test.** Every case is `live-observed` / `specified-not-run` (`greenfield-kickoff.json:6,33,49,64,79,94,110,124`). The pattern `a-golden-dataset-case-counts-only-when-a-named-test-passes.md` says an unrun case is unenforced; until a test asserts each case id, the dataset catches no regressions. Live observation is observable but not automatically gradable. | For each case, either (a) write a scriptable test whose name starts with `[<case-id>]`, or (b) mark it `live-only` with a named owner and a planned observation script. Add negative controls for skipped/todo results. |
| E3 | medium | dependency-blind-spot | **`definition-to-first-version` does not verify the package-less ship route.** The pitch depends on `package-less-ship-verification` (`pitch.md:93`) and the wrapper issue `package-less-bundle-ship-wrapper-cannot-select-checks.md` remains unresolved. If that dependency regresses, the first-version pitch created by kickoff cannot ship, but all kickoff cases would still pass. Observable in a disposable directory; gradable by exit code of `/ship-pitch` on the generated first-version pitch. | Add an expected action: the first-version pitch must reference an owner-approved direct-check fallback and must not create a temporary `package.json` or application-specific verifier. Bind to a test in `package-less-ship-verification`. |
| E4 | medium | adapter-drift | **Cross-vendor adapter parity is unchecked.** The solution adds 4 skill adapters (`pitch.md:25`), but the cases are vendor-agnostic behavior checks. Prior issue `instruction-copies-drift-into-contradictions.md` shows copied instructions drift when no test compares them, and `installed-skill-wrappers-ship-as-orphans.md` shows source-owned wrappers can ship as orphans. A regression where adapters invoke different prompts or ship stale pointers is not caught. Observable by reading adapter files; gradable by a contract test. | Add a parity case/test that every vendor adapter either byte-matches the canonical skill file or points to it with an allowed pointer pattern, and that `bundle-sync` excludes source-owned skill directories. |
| E5 | medium | input-variety-gap | **Non-linear interview paths are missing.** Cases are single-session, mostly linear scripts. The pitch requires every statement to be `decided`/`proposed`/`open` and save-as-you-go (`pitch.md:39-41`), but only `interrupted-and-resumed` tests restart. There is no case for revising an earlier answer after technology was discussed, or for deferring a required answer and returning later. Observable in a scripted multi-turn conversation; gradable by the final state labels. | Add a `mid-interview-revision` case and a `deferred-then-continued` case, each bound to a state-label assertion test. |
| E6 | low | ownership-marker-gap | **Respect for non-kickoff files is only partially tested.** `not-actually-empty` and `interrupted-and-resumed` forbid overwriting existing context/rules, but no case exercises the ownership-marker rule from `a-report-never-overwrites-a-file-it-did-not-write.md`: a resumed kickoff must not replace a definition file written by something other than kickoff. Observable in a fixture directory; gradable by file content and marker check. | Add a resume case where an existing `.project/context/product.md` without the kickoff ownership marker is detected and left untouched, with the difference shown to the user. |

## Summary

The biggest pre-bet risk is **E1**: a known failure class (host built-in shadowing) is unrepresented in the golden case, despite being the exact rabbit hole the pitch pushed to `/plan`. The second largest is **E2**: even if the cases are well designed, none is currently bound to an executable test, so the dataset provides no automated regression signal until that wiring is added.
