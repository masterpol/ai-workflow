# Pitch: restore-vendor-adapters

**Date**: 2026-10-08 • **Appetite**: big-batch (at most 15 implementation files; generated stub output is ~90 small pointer files counted separately)
**Stack**: workflow tooling

## Problem

This checkout is missing the OpenCode and Codex adapter directories (`.opencode/`, `.codex/`, `.agents/skills/`) that the bundle expects. `workflow-doctor.mts` requires every canonical skill/agent to have these pointer stubs, and without them OpenCode cannot discover workflow phases or subagents. As a result, `node ai-framework/scripts/orca-run.mts start --phase shape --vendor opencode` has no host-level wiring to land on, and live Orca coordination from OpenCode is impossible.

- `.project/knowledge/decisions/workflow-tooling-pitches-share-standing-no-gos-and-design-answers` — Cursor mirrors are produced by `skill-vendors.mts cursor-mirrors`; the same script can be extended for other vendors.
- `ai-framework/scripts/workflow-doctor.mts:524-588` — validates that every canonical skill has `.agents/skills/{name}/SKILL.md` and `.opencode/commands/{name}.md`, and every agent has `.opencode/agents/{name}.md` and `.codex/agents/{name}.toml`.
- `ai-framework/scripts/skill-vendors.mts:154-180` — existing `cursor-mirrors` generator writes only missing byte-copy mirrors.
- `ai-framework/integrations/harnesses.md` — OpenCode model routing and adapter contract.

## Solution sketch (breadboard)

**Places:** `skill-vendors.mts` generator, `.opencode/` descriptor tree, `.codex/` descriptor tree, `.agents/skills/` pointer tree, doctor/validator tests.

**Affordances:**
- `node ai-framework/scripts/skill-vendors.mts opencode-mirrors [--root .] [--apply]` — preview/create OpenCode commands, agents, `opencode.json`, `package.json`, and the `token-consumption.ts` plugin stub.
- `node ai-framework/scripts/skill-vendors.mts codex-mirrors [--root .] [--apply]` — preview/create Codex agents, `.agents/skills/`, `config.toml`, and `hooks.json`.
- A shared helper that derives the correct `model:` / `model =` / `model_reasoning_effort` from the canonical file's declared capability profile, matching `harnesses.md`.

**Connections:** canonical `.claude/skills/*` and `.claude/agents/*` are the source of truth. Generator reads profile from each canonical file, writes pointer stubs that load the canonical path, and reports created/differs/current like `cursor-mirrors`. Generated stubs are committed as bundle output. `workflow-doctor` and `setup-validator` then pass.
