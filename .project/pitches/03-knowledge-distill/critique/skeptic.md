# Skeptic critique of selective source loading

| ID | Severity | Type | Finding | Suggestion |
| --- | --- | --- | --- | --- |
| S1 | medium | Adoption | The pitch shows interest from the owner and participation from pilot readers. A recurring opt-in user is still unverified. The pitch excludes phase callers, the plan describes hypothetical users and scopes only CLI code, tests, and documentation, and the pilot leaves independent use open. The plan therefore has no named person or agent who needs repeated research on a real topic, knows when to invoke the loader, and owns its catalog. [Pitch, lines 22–28 and 86–88](../re-shape-retrieval.md#L22-L28) · [Plan, lines 5–11 and 23–28](../plan.md#L5-L11) · [Pilot, lines 24–30](../pilot/selective-routing.md#L24-L30) | Name one user, their recurring question, and who owns the real catalog. Have that user run the documented opt-in flow on their own question before committing to the full build. |
| S2 | medium | Savings baseline | The reported 54.21% is against 3,555 words of five-card bodies, so the 30% build target remains unverified against the current retrieval policy. Plain Graphify queries now rank up to five knowledge paths using entry IDs, labels, and tags, then run the native traversal. With native execution stubbed, the current checkout ranked the required pilot source second for the first and second queries and omitted the third query’s required source from the ranked five. This gives the baseline a cheaper first pass on some questions, with further search still potentially needed. At the pilot candidate’s 1,628 words, a baseline of at least 2,326 words would be needed to clear 30%. [Pilot counts](../pilot/selective-routing.md#L12-L20) · [Required pilot sources](../pilot/selective-routing-evidence.json#L150-L212) · [Ranking and limit](../../../../ai-framework/scripts/graphify.mts#L393-L440) · [Query dispatch](../../../../ai-framework/scripts/graphify.mts#L796-L804) · [Plan measurement](../plan.md#L32-L36) | Specify a baseline policy that uses the ranked paths, opens enough cards to answer with evidence, and continues search when the first pass is insufficient. Compare answer quality and all model-visible text across both policies before relying on the savings estimate. |
| S3 | medium | CLI output contract | The plan promises JSON on a successful selection and Graphify output on fallback. Graphify writes the ranked header through `deps.io.stdout`, while the native traversal inherits the process streams. A harness that observes only the injected writer will see the header without the traversal and can undercount fallback even when the exit status propagates correctly. [Plan, lines 13–19 and 27–36](../plan.md#L13-L19) · [Graphify query dispatch](../../../../ai-framework/scripts/graphify.mts#L796-L804) · [Node runtime, lines 201–206](../../../../ai-framework/scripts/runtime/node.mts#L201-L206) | Document both output forms and specify that the existing disposable CLI test captures process stdout and stderr. Assert the ranked header, a distinct traversal marker, the refusal reason, and the native exit status. Use that same capture boundary for the live word count. |

The ranking check used Node and `/usr/bin/true` in place of native Graphify. Native traversal, end-to-end word counts, golden cases, fallback under Node and Bun, and independent adoption were outside this verification.
