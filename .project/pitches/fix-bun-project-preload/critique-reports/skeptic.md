# Skeptic review of fix-bun-project-preload

## Findings

| ID | Perspective | Severity | Type | Suggestion |
|---|---|---|---|---|
| S1 | skeptic | high | missed-rabbit-hole | Extend the trusted-bundle rule to the doctor's nested Graphify launch. The validator selects its bundled Graphify and doctor relative to the running module (`ai-framework/scripts/setup-validator.mts:53,225,261`), but the doctor selects Graphify from the checked working tree and sends it through the selected runtime (`ai-framework/scripts/workflow-doctor.mts:394–397,686–694`). A trusted doctor started from a separate installation therefore hands the checked tree's Graphify entry to Bun or Node, even after both parse branches are replaced. Use the running bundle's sibling helper and cover both the direct doctor and the validator-to-doctor route. The same class of project-script execution was previously found in this repo (`.project/knowledge/patterns/a-report-over-an-untrusted-tree-runs-only-bundle-code.md:20–22,38–42`). |
| S2 | skeptic | medium | resolution contract | Specify where executable trust comes from before searching for Node. Rejecting a resolved path inside the checked tree alone can still admit a tree-controlled PATH entry that points outside the tree, or an outside launcher that delegates back to the tree. The current launcher uses a bare runtime name for either cross-runtime switch and forwards the environment (`ai-framework/scripts/runtime/entry.mts:20–35`). The direct CLI reaches that switch before either command's main runs (`ai-framework/scripts/runtime/cli.mts:10–25`). Limit executable selection to a Node parent executable or a trusted installation path independent of the checked tree. Check both the candidate location and the canonical target, define whether wrappers are supported, and use the selected absolute executable via a parse-specific spawn that never re-enters runner selection. Resolve the cross-runtime switch under the same trust policy or explicitly bound the claimed protection to an already trusted bootstrap. The prior Orca launch review recorded the same verify-versus-spawn mistake (`.project/knowledge/patterns/a-gate-spawns-exactly-what-it-probed.md:13–23`). |
| S3 | skeptic | medium | incomplete coverage contract | Treat syntax coverage as an explicit result across both commands and their caller. Setup currently records an info row for skipped files, then counts those files as parsed (`ai-framework/scripts/setup-validator.mts:291–294`). The doctor can report READY and exit 0 after info-only skips (`ai-framework/scripts/workflow-doctor.mts:452–460,1136–1161`), and the validator re-labels any zero-failure doctor result as passed (`ai-framework/scripts/setup-validator.mts:260–267,326–341`). One ship check also consumes exit status alone (`ai-framework/hooks/scripts/pre-ship-verify.mts:116–123,248–253`). Keep static and presence checks available on Bun-only hosts, but carry parsed, failed, and unavailable counts into JSON, the human summary, and the nested result. Decide whether any caller requires full syntax coverage and make that caller enforce it. Cover all-skipped and mixed results. A Bun-only host loses every check routed through the Node parser, not just the feature used by old Node for TypeScript. It also cannot use the currently documented Node bootstrap for an isolated Bun run (`ai-framework/scripts/runtime/README.md:46–50`). |

## Checked in the checkout

- Traced the shared launcher through both child APIs and the direct CLI handoff. Workflow-started Bun eval, script, and build launches get the shipped isolation flags. Bun tests bypass them as intended (`ai-framework/scripts/runtime/entry.mts:12–45`). The direct generic CLI imports its caller-selected script before dispatch (`ai-framework/scripts/runtime/cli.mts:39–49`). That interface intentionally starts code and is separate from the two diagnostic entry points.
- Traced the setup validator's Graphify, doctor, and TypeScript child launches and the doctor's parse, Graphify, OpenCode, uv, and Git paths. The bundled Graphify `--check` returns before the external Graphify rebuild (`ai-framework/scripts/graphify.mts:789–829`). The doctor also invokes bare `uv` and uses `hooksDir`, which invokes bare `git`, from the checked directory (`ai-framework/scripts/workflow-doctor.mts:737–745`, `ai-framework/scripts/graphify.mts:711–716`). On a Node parent the doctor invokes `opencode debug config` in that directory. On a Bun parent it skips this discovery (`ai-framework/scripts/workflow-doctor.mts:394–397,664–683`). If the read-only promise covers the whole report, define trusted external command resolution and the policy for live OpenCode discovery. The call site shows where discovery starts. Whether OpenCode loads or executes project code in this mode is unverified.
- The current TypeScript Node eval reads the target as text and calls `stripTypeScriptTypes`. The existing JavaScript branch passes the target to `node --check` (`ai-framework/scripts/setup-validator.mts:51–52`, `ai-framework/scripts/workflow-doctor.mts:25,452–457`). The current doctor's fixed script catalog lists TypeScript paths, although it has a JavaScript branch (`ai-framework/scripts/workflow-doctor.mts:1048–1057,1115`). Add explicit coverage for that branch if it stays in the pitch. The doctor's separate runtime-boundary scanner reads bytes and scans text without invoking the Bun transpiler (`ai-framework/scripts/workflow-doctor.mts:120–154`, `ai-framework/scripts/runtime/validate.mts:239–248`).

## Inferred or unverified

This was a static review. Runtime marker behavior for the two Node parse forms, executable resolution across hosts, and the Bun-only end-to-end result of the proposed change remain unverified. The current parse callers inherit the launch environment. The pitch explicitly excludes hostile `NODE_OPTIONS` and `BUN_OPTIONS` (`.project/pitches/fix-bun-project-preload/pitch.md:58`). Keep that boundary visible if the parse child continues to inherit host settings. The Graphify finding follows from the current path and launch arguments. It does not depend on a parser feature, executable spoofing, or a hostile installed copy of the running bundle.
