## Checked, no defect found

- **Mapping:** `phase-commands.mts` is correct. In a probe, `mapClaudeEvent` gave `ship-pitch [["phase.started","ship"]]` and `ship []`. `FLOW_PHASES` is built from the map values, so it still holds `ship`. `flow-join`, `orca-run` `START_PHASES`, `skill-defaults`, `add-skill` and the metrics rank keep the phase `ship`. The only non-test callers of `resolvePhaseContext` are `token-consumption` and `workflow-capture`, and both pass command or skill names.
- **consolidation-migrate:** `git show HEAD:ai-framework/templates/project/knowledge/README.md | shasum -a 256` gives `99e824eb…023d5`, which matches the added hash.
- **Text sweep:** in the `-U0` diff of the swept docs, I found no phase name or verb that was wrongly renamed. The gate choices `[1] ship / [2] hold` and the phase tables keep `ship`. F1 covers the contradictions I found.
- **Mirrors:** `cmp` over every `.claude` skill and agent that has a `.cursor` copy printed no difference. The four moved adapters differ from their HEAD versions only by the rename.
- **Old-install upgrade:** the old script's apply keeps the 4 `ship` files and records them well enough that the new script sees them as `[unmodified]` and prunes them on the second apply.
- **Tests:** in the scratch copy I ran the `phase-commands`, `command-name-guard`, `consolidation-migrate`, `skill-defaults`, `workflow-contracts` and `instruction-loading` tests under Node: `tests 90, pass 89, fail 0`. I did not identify the one test that is neither a pass nor a fail.

- One test and guard-probe command ran past the 20-second limit and was moved to the background. It finished; the exit code 1 came from the trailing `ls` of the nonexistent `.cursor/rules`.
- A `.cursor/zz.mdc` guard probe was not reported, because `.mdc` is not a scanned extension. The repository has no `.mdc` files, so I did not file it.
