# Knowledge-historian findings: orca-balanced-role-pools

Read-only review of `.project/pitches/orca-balanced-role-pools/pitch.md` against `.project/knowledge/`. Entries already listed in the pitch's "Knowledge consulted" section are excluded.

| ID | Severity | Type | Finding | Suggestion |
|----|----------|------|---------|------------|
| K1 | high | missed-pattern | The pitch adds a `run-current` call per dispatch and a ledger `runId`, but does not cite `.project/knowledge/patterns/verify-run-binding-before-orca-dispatch.md`. That pattern requires verifying the bound Run (objective + coordinator) after readiness, creating a Run only when absent, and stopping to ask for an unrelated binding. Without it, a null or mismatched Run could be silently accepted and `runId` would fall back to live-only load. | Add the pattern to "Knowledge consulted" and extend rabbit holes: verify `run-current` objective/coordinator match before claim, block on unrelated binding, and preserve the Run ID. |
| K2 | high | missed-pattern | The pitch adds a new live CLI call (`run-current`) but omits `.project/knowledge/patterns/a-doctor-check-stays-offline-and-the-live-check-is-its-own-command.md`. The workflow doctor has a standing guarantee that it never runs Orca; new CLI commands must be captured in the committed contract snapshot and validated offline, with the live diff as an explicit `orca-contract.mts --check`. | Add the pattern, scope an update to the contract snapshot / `USED_CONTRACT`, and keep the doctor sentinel test green after the new command is added. |
| K3 | medium | missed-issue | The pitch pushes the first real OpenCode pick to `/plan` but does not cite `.project/knowledge/issues/orca-workers-differ-from-the-coordinator-environment.md`. That issue records that a worker's `orca` binary, PATH and server state differ from the coordinator's — exactly the environment where `prepareOpencode()` and the first opencode dispatch run. | Add the issue and require a live smoke per vendor (at least one opencode dispatch) in `/build`, recording worker-side state rather than only coordinator-side checks. |
| K4 | medium | missed-pattern | The pitch will change coordinator guidance across `orca-vendors.md` and phase docs, but does not cite `.project/knowledge/patterns/one-owner-per-instruction-topic-guarded-by-contract-tests.md`. The pattern says name one owner file per topic, make other mentions pointers, and guard agreement with a contract test. Without this, the new "use `assign` by default" guidance can drift between `orca-vendors.md` and the build/audit/critique skill docs. | Add the pattern, name `orca-vendors.md` as the owner for dispatch guidance, and add a `workflow-contracts.test.mts` assertion or cross-doc pointer check. |
| K5 | medium | missed-issue | The pitch notes "the guidance change is model behaviour" but does not cite `.project/knowledge/issues/instruction-copies-drift-into-contradictions.md`. That issue shows copied instructions across skills, specs and mirrors drifted into contradictions that changed agent behaviour; the planned updates to build/audit/critique phase docs and their vendor mirrors multiply the copy surface. | Add the issue, refresh vendor mirrors in the same change, and plant a canary in reviewers' scratch copies to verify they read the updated guidance. |
| K6 | medium | missed-pattern | The pitch parses `run-current --json` output but does not cite `.project/knowledge/patterns/a-receipt-field-reaches-a-reason-only-as-a-bounded-token.md`. While `runId` is on the success path, any CLI output is untrusted and should be validated as a strict token; error text must never be echoed into a reason or ownership decision. | Add the pattern and ensure the `run-current` parser validates `runId` as a closed-shape token and treats every malformed response as "absent `runId`" rather than echoing CLI text. |
