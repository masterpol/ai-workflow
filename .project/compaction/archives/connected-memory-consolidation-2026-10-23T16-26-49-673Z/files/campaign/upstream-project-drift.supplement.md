## Problem and pitch

The owner fixed the same workflow bugs by hand in LAH, RN and climbing-lab-monorepo because each project carried local edits to `ai-framework/` that never reached the base bundle, and every `bundle-sync` from 2.22.5 reported conflicts instead of a clean update. Epic `workflow-v3`, pitch 1 of 5 (order: upstream-project-drift, unified-toon-config, orca-engines-range, orca-role-pools, workflow-v3-rollout). Affordances: a drift ledger row per differing file (origin project and commit, classification upstream, project-local, drop or superseded-by-pitch-N, reason); back-port upstream rows with their tests, refresh Cursor mirrors, bump to 2.23.0; document the right home for project-local rows (`.project/rules/`, TOON config) so the next sync is clean; verify with `bundle-sync` dry runs from the new base against each project.

Pitch-time drift inventory (all projects synced from 2.22.5 on 2026-10-09): climbing `ddf1b77` accept Orca 1.4.223 or later and `e2c28a2` reject oversized or non-canonical versions; `8bd0c97` OpenCode V2 token-consumption plugin compatibility; `c376bda` graphify consistent on dangling edges (the base already held an uncommitted 12-line partial port); `406ecc5` rules for unrepresentable invalid states and exhaustive switches; `60063cc`, `d6f624c`, `088d6d1`, `3b88542` Linux runtime, task ownership and doctor fixtures touching `orca-apply`, diff-admit, dispatch, evidence, ledger and eval-grader; climbing README, SETUP and `.project/workflow-doctor.json` project-local. LAH `bd40d5d` Orca 1.4.224 floor with a loose `isSupportedVersion`, and an `orca-vendors.json` (3 workers, `worker` role, cap 4) that current policy rejects. RN Orca 1.4.224, the Orca start hooks, `pre-ship-verify`, `stuck-uphill-detector`, `hooks.json`, rule rewrites and docs differences. Knowledge consulted at pitch time: standing workflow-tooling no-gos, effective sync bases, Cursor byte mirrors refreshed in the same change, running gauntlets under both runners (LAH and RN use bun, climbing uses node), and mutant proofs for back-ported guards.

The wave 3 ordering had no technical reason.
- D7: climbing's runtime was proven on Linux only; on macOS its `runtime.test.mts` failed 2 to 3 of 52 tests and copying it broke the Bun gauntlet (58 failures). Three fixes: `EPERM` from `kill(-pgid)` on macOS means the group is still exiting (`posixGroupIsRunning` and `killGroup`; the 5 s exit proof remains); `createNodeDeps` and `createBunDeps` return `child: { ...nodeChild }` so tests replacing `deps.child.runSync` no longer leak fakes in Bun's single process (regression test added); [upgrade.test.mts](../../../ai-framework/scripts/runtime/upgrade.test.mts) tolerates the missing `.codex/hooks.json` startup wiring of an old install, clearing 3 pre-existing failures (owner decision 3). The Linux check (owner decision 4) ran in Docker `node:24` (24.22.0, Linux 6.12): runtime, invariants and test-helpers 69 pass, 0 fail, 5 skipped. Remaining flakiness only under full-suite load: "descendant ownership after timeout/output" (node and bun) and the orca-eval-grader mutation proof "settle without evidence"; each passes when its file runs alone. The S9 gauntlet then showed a further macOS EPERM site (the `exit` handler's group SIGKILL in [node.mts](../../../ai-framework/scripts/runtime/node.mts)), fixed the same way, with the test failure message now carrying the cleanup cause.
- D8: every OpenCode worker failed at `agent_readiness` while a stale `opencode serve --service` held its port (PID 13944, started 2026-10-15; climbing hit the same failure on 10-15); freeing the port fixed it and later workers share the server the first one starts. It was ordered after S5 because S4 also edits `orca-run.mts`. Live smoke freed PID 40797.
- D9: the S3 port covered only the version check, so the S4 worker added `watchCleanup` wrappers; the coordinator ported the missing launch-gate and probe-runner hunks (`4e8a99e`) and took climbing's dispatch and reconcile, removing the wrappers while keeping the worker's `schemaVersion` handling as the old-record proof.
