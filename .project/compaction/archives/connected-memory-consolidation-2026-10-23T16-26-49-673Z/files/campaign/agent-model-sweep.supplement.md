The pitch was one big-batch split into three sequential bets. Bet 1 (shipped earlier at f5b3eb0) made the doctor read the toon `models` block, added the mandatory toon check and made `extractAgentProfile` read `profile:`. This record covers Bet 2, the canonical sweep: commits 9a336a2 (sweep) and 7c7643c (audit cycle 1 and 2 patches). Bet 3 stayed open.

- Docs: [extending](../../../ai-framework/docs/extending.md), [vendors](../../../ai-framework/docs/vendors.md) and harnesses state that Claude Code does not read `ai-workflow.toon` and that the profile is declared once. CHANGELOG 2.28.0; VERSION 2.27.0 to 2.28.0.

## No-gos and resolved rabbit holes

No-gos held: no agent prompt-body changes (`profile:` is frontmatter), no new dependencies or network, no secrets or `.env`, no TOON grammar or `config.mts` changes, no model aliases or fallback chains. `model:` in `.opencode/agents/*.md`, `.codex/agents/*.toml` and `.opencode/commands/*.md` stays for Bet 3. The original pitch no-go deferred all `model:` removal to Bets 2 and 3; Bet 2 removed it only from canonical agents.

Resolved: the doctor derives the profile from the frontmatter key, not a body banner (none exists on agents and body changes are a no-go) or the model id. Mirror consistency anchors on the line, not a substring (see [substring check issue](../../knowledge/issues/substring-hook-wiring-check-accepts-echoed-commands.md)). The exception tables (`skillProfileOverrides`, `skillModelOverrides`, `skillReferencePatternOverrides`) and project-owned routing (`modelRouting: project`, `.project/workflow-doctor.json`) were preserved. Removing `agent.build.model` is safe only because a top-level model is set, which preserves deep primary-agent routing. The warn rather than fail rule for a missing `profile:` and the same-commit Cursor regeneration (no intermediate drift window) were also settled here.

Claude Code does not read the toon. The critique recorded that an omitted `model:` makes Claude Code use the parent session model (or a per-invocation subagent override), so `profile:` is consumed by the doctor and dispatchers, not the Claude Code runtime. This was documented in harnesses; the sources record no empirical test of that runtime behavior.

Pushed to no-go in the pitch: per-role overrides beyond fast/standard/deep, generating vendor config from the toon, runtime model switching, and preserving the 28 command-intended models (commands without `model:` inheriting the session model is a documented behavior change, not a bug).

## Plan and profile mapping

Seven scopes: S1 canonical frontmatter, S2 Cursor mirrors, S3 opencode config, S4 doctor cleanup, S5 tests and invariant, S6 docs, S7 release. S1 and S2 had to land in one commit because the byte-identity test fails if the canonical edit ships alone; S4 precedes S5; S3 and S6 are independent; S7 last. No scope used a subagent. `cursor-mirrors` without apply only creates missing files, so differing mirrors are reported and must be copied manually, then gated on empty `differs`. Edits were anchored to `^model:` inside the frontmatter block. The add-the-replacement-before-removing-the-override rule applied to the opencode top-level model. The plan's appetite file-count cap (about 33 to 38 files) was acknowledged as a bookkeeping breach for a scripted sweep. The plan's S7 target was 2.27.0, coordinated with orca-role-pools Wave 2; it shipped as 2.28.0.

## Build decisions and incidents

- The planned separate S2 shipped atomically with S1. The shell one-liner for the opencode contract became a real doctor test because shell checks do not run in CI.
- Precondition incident at S1 start: `vendor-model-toon` S1 was marked done by user override but was uncommitted, with open writer-literal, config-migrate (65) and config (28) failures (93 in total). Options logged: A commit as-is and carry the failures; B close the three audit must-fixes first, then commit; C fold the regex updates into S1 (big-batch). Lesson: a dependency is satisfied only when committed and green, not hill-done. The entry still reads open; the plan later recorded Bet 1 as shipped (f5b3eb0).
- Codex effort deviation: the toon is authoritative, so the doctor failed `architect.toml` and `planner.toml` (`xhigh`) against a local `models.codex.deep.effort: high`. The shipped example toon uses `xhigh`. The local toon was changed to `xhigh` in audit cycle 1 (doctor 0 fails). The alternative, lowering the two TOMLs, would change real reasoning effort; the project owns that choice.
- Mandatory toon: `checkToonMandatory()` runs once before the agent loop and emits one top-level result (fail when absent, refused or missing the models block; pass reports schemaVersion 3 and 3 vendors by 3 profiles). See [mandatory config pattern](../../knowledge/patterns/mandatory-config-files-emit-one-top-level-failure.md). Doctor tests went 45 to 48 with three mutant tests; the docs now point at the toon as the source of truth.

## Knowledge and lessons

Promoted at ship: mandatory config files use one top-level check with per-consumer demoted warns ([pattern](../../knowledge/patterns/mandatory-config-files-emit-one-top-level-failure.md), reaffirmed by the cycle 1 patches); warn text patches need their own test assertion; warn text must be self-consistent with the code it ships ([pattern](../../knowledge/patterns/warn-text-must-be-self-consistent-with-the-code-it-ships.md)). A fourth lesson from the upgrade-test follow-up is that test fixtures which copy the bundle must seed the new mandatory config, reusing the `cpSync` skip plus example copy from the skill-defaults and skill-vendors tests. Also kept: atomic canonical plus mirror commits; a hill-done dependency is not committed and green; real tests instead of shell one-liners for CI contracts.
