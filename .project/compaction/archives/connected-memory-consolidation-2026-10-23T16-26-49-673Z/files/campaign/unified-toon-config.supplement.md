## Design and rabbit holes

Resolved in the pitch (pass 3):
- Primitives first: `wxRename` (exclusive `wx` write of a temp file plus `renameSync`, ported from `orca-apply.mts`), `inspectPath` + `readBoundedFile` ported from `orca-policy.mts` (lstat-walk every component, `O_NOFOLLOW|O_NONBLOCK`, dev/ino compare before and re-inspect after read), `oexLock` (O_EXCL lockfile, EEXIST gives a fixed-text recovery message), named validator slots, and `errorCodes` so every guard has a fixed-text code a mutant can assert on.
- Parser: strict in-repo subset because the bundle has no `package.json` or npm install; objects by indentation, scalars, quoted strings, inline primitive arrays `key[N]: a,b`; anything else refused with line and column. Linear line scanner, size cap, timing test; no backtracking regex on the file.
- Precedence: process env > TOON > defaults.
- `roles.<role>` accepted as a string or an array of distinct strings (within-role duplicates and `__proto__`/`constructor`/`prototype` refused); pool behavior left to orca-role-pools; the reader flattens to `Record<string,string>` for `orca-start`.
- Seams frozen by signature and payload: `readPolicy(root,deps)`, `report().roles` at `Record<string,string>` (internal `coordinators.<v>.roles` widenable by pitch 4), `orcaMultiAgentEnabled`, `loadModes`, `loadWorkflowEnv(fs,path,root,env)`, the launch-gate lstat walk. Diff criterion (X12): no `orca-*.mts` edit except `orca-policy.mts`, 7 fixture tests, the `orca-preflight.test.mts` filter and the `orca-launch-gate.mts` doc line.
- Reuse `runtime/migrate.mts` `regular()` and `EntryMigration` rather than a second vocabulary (only the type was reused, d30).
- Migrator `--force` three branches: absent writes; valid differing file refuses unless `--force`, which uses dual-hash tracking (canonical bytes written + parsed model) to tell hand-edited from stale; unparseable file refused and moved to `.rejected`, never overwritten. `--apply` re-parses in a fresh subprocess, not the running module cache.
- Unknown `schemaVersion` refused; integrations map open with unknown keys reported; lexer fails closed on unreadable, oversize or symlinked files.
- Bundle-sync: `ai-workflow.toon` is instance data, never synced, proved by a mutation-checked test and a simulated old-version sync; bundle-sync is not a config writer, the migrator owns the lock. `SETUP.md` and `README.md` added to `FLAGGED_FILES`.
- Doctor's legacy-files walk excludes `.project/records/config-migration/`. Setup-validator check named `Workflow config`: absent is `info`, invalid is `fail`; the rollout gates on `--json` `results[]` by name and status, never exit code; no `--validate-absent` flag.
- Mirror refresh after every canonical skill edit; `.agents/skills/build/SKILL.md` is a stub and is not edited; AGENTS.md and CLAUDE.md byte-equal.
- `ai-framework/integrations/orca-vendors.example.json` kept in place (8 test files read it by relative path); content edit belongs to orca-role-pools. Optional templates never go into `templates/project/` (the doctor scaffold check requires every file there).
- Bun: `runtime/bun.mts` overrides only async read/write/exists, so sync `wx`+rename is runner-identical; do not pin raw `node:fs` (it breaks `deps.fs` injection for `memoryFs` mutants); one regression gate asserts the Bun adapter never overrides `writeFileSync`.

Pushed to no-go: role arrays behavior and higher worker caps, per-pool and per-coordinator concurrency (orca-role-pools); version ranges (orca-engines-range); `notion` and `orca.cliCommand` keys (no consumers); `flock`; raw `node:fs` pin; `--validate-absent`; templates under `templates/project/`.

## Standing constraints

- TOON only; no YAML, JSON5 or TOML alternative.
- No secrets in the file; `.env` is never read.
- No auto-migration on read; migration runs only through the CLI (or `/setup` calling it).
- Standing workflow-tooling no-gos apply.
- Held at ship: legacy files never deleted by the migrator; no `flock`; no regex backtracking on the TOON file (an audit ReDoS was fixed). Deviation: `maxConcurrentWorkers` widened to 1..16 by the owner (d46/d47) and `orca-policy` follows.

## Schema v2 reshape

## Delivered behavior

- TOON branch semantics (d13): a present and valid TOON wins; a missing file falls back to legacy; a present but refused file contributes nothing (env) or `refused`/`malformed` (policy) and never falls back. A narrow `fs` makes `loadConfig` refuse rather than fall back (d17, doc corrected in d).
- `readPolicy` maps the model into the legacy JSON shape and reuses `validatePolicy`; array role targets report their first element.
- Migrator decisions (d32): a differing valid file needs `--force`, which always backs up first and reports `stale` or `hand-edited`/unknown; an unparseable file on `--apply` is renamed to `ai-workflow.toon.rejected` (or a stamped name, never overwritten), exit 1, unaffected by `--force`; unregistered slots, symlinks, oversize and escapes refuse with no move; dual-hash record `.project/records/config-migration/state.json`, backups `.project/records/config-migration/<stamp>/`; `.gitignore` appended only when it exists; hidden `--verify` is the subprocess re-parse entry; a failed post-write check restores the previous bytes. The migrator does not convert v1 keys: `--force` replaces an unsupported file from legacy JSON or defaults and keeps a backup (d49).
- Migration is lossy (d31): `caveman.enabled:false` maps to `off`; per-phase `caveman.phases` has no TOON slot; with a valid TOON file, `modes.json` phases and default are ignored (d40).
- `loadModes` reads TOON `skills.modes` first and falls back to `modes.json` only when TOON is missing; present-but-invalid TOON throws; state-snapshot and doctor read through it; `token-consumption.mts` keeps its direct read (d39).
- `oexLock` has no automatic stale steal: a leftover lock gives `OEX-LOCK-BUSY` until removed by hand; release is idempotent (d9).
- Local per-component reader `readSafe` in the migrator and a pinned `readLegacyFile` in `env.mts`; `linkSync` added to the runtime fs types (d30, d50).

## Lessons kept here

- A downstream mutant scope is the first real consumer of a producer's error contract (d5, d6).
- A mutation can be masked by a second guard; add an isolating case before counting it.
- Literal grep-count exits invite padding (d7, d16); under `grep -E`, `\|` is a literal pipe (d28).
- `skill-vendors cursor-mirrors --apply` only creates missing mirrors; refresh an edited mirror by copy (d22).
- An untagged release commit blocks a tag-based branch gate; a local tag fixes the build but not the published namespace.
- The gitignored root `ai-workflow.toon` leaks into fixtures copied from the bundle; legacy-path tests must delete it (d41, d45, d47).
