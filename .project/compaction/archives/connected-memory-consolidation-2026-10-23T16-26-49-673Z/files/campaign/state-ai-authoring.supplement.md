## Scope and contract

Problem: the owner wanted the report to explain architecture, history, risks and the token story, written by the AI with the script only carrying it into the page; nothing marked that output as proposed, flagged it stale, or kept one bad answer from breaking a page.

Five slots: `overview` and `risks` on index, `architecture` on structure, `history` on pitches, `tokens` on metrics; `state.html` stays facts-only. Fragments live in `.project/reports/fragments/` (`<slot>.draft`, `<slot>.fragment`, `.round.json`), ignored by git through the existing `.project/reports/*` rule. Stamped file header (LF, at most 1,024 bytes, fixed order): `state-fragment 1`, `slot`, optional `snapshot <64 hex>`, `body-sha256`, `model`, `stamped`, `---`, then the sanitizer's canonical body. A broken grammar is `invalid`; a missing or non-hex snapshot line is `stale`. Model id must match `^[A-Za-z0-9._:/@+-]{1,80}$` or is recorded as `unknown`.

Hash: SHA-256 of canonical JSON (sorted keys, depth at most 32) minus volatile paths: `generatedAt`, `metrics.value.updatedAt`, `metrics.status`, `metrics.note`, `knowledge.status`, `knowledge.note`, `risks.staleKnowledge`, `architecture.graph.value.mtime`, `architecture.graph.status`, `architecture.graph.note` (the contract doc pins this list; a drift test compares it). Counts such as completions still move the hash, so slots go stale after most completions; per-slot hashes are a no-go.

`stamp` order: directory guard, round valid and current, attempt cap of 2, bounded draft read with identity record, draft not older than the round, sanitize (markers disabled), citation check against the current snapshot, at least one citation, cited files at most 65,536 bytes (`evidence-truncated`), no links in `tokens`, atomic write, identity re-check then draft delete. `loadFragments` re-runs the checks on every load plus canonical form and body hash.

Resolved at shape: an absent `fragments/` directory emits empty slots (keeps redesign's byte identity); a present directory shows a one-line reason per bad slot. Prompt injection is handled deterministically where possible (allow-list, evidence paths in the current snapshot, bound equal numbers, one citation minimum); a qualitative claim with no number cannot be proven false by code, so the label, evidence footer and live cases carry that risk. Pushed to /plan: coupling to sanitizer and redesign contracts, and the per-vendor live harness. Deferred: per-slot hashes, a persistent strict setting (strict is a CLI flag only), a qualitative-claim checker, a live Cursor run (recorded `not-run`).

Critique (five perspectives, 2026-10-19) rulings kept as defaults: stamp treats the draft as untrusted; summary line always printed; hash excludes clock-derived fields; independent adversarial review before live verdicts; per-verdict re-check commands; module renamed `state-fragment-inject.mts`; the `tokens` slot reads `state.json` only; seeded known-bad fragment per live case so a vacuous grader is caught. Owner chose Bet.

Plan corrections to the pitch: the sanitizer is three modules; redesign exports no class/token/marker lists (so `FRAGMENT_CLASSES` and container CSS went into `state-design.mts`); arrow markers cannot work under the inert-page rule (diagrams use lines and text); the 64 KB cap means large files (for example done-work, the graph) are cited through `<data>` bindings, not links; a canonical hand-written body cannot be told from a stamped one (no secret), so the footer says "not verified"; `status` writes `.round.json`; live cases assumed token totals and audit data the snapshot lacked (graders read the agreed readings); `state-deep-evidence` cases must stay out of the 22-case file.

## Standing constraints

- No script calls a model or the network; authoring happens only in the host session; no subagents or dispatch in the step.
- Writes only inside `.project/reports/fragments/`; `state.json`, `status.md`, `runs/` and `state-snapshot.mts` untouched; no snapshot `schemaVersion` change; the 22-case dataset unchanged and not converted to TOON.
- The AI reads only files `state.json` cites; the `.env` canary never appeared in any of 72 run logs.
- A rejected draft is never repaired; no reuse across a changed hash; no stale fragment shown as current; no AI content in `state.html`; fragments cannot use `status-*` or `ai-analysis` classes.
- Fragment content is never echoed (closed reason codes only).
- Weaker than they sound: the retry cap and draft-age check depend on the model cooperating (`.round.json` is unauthenticated, D27); a same-user process racing the script can redirect one by-path write or delete in `fragments/` (D33, accepted by the owner).

## Live harness and matrix

## Knowledge and lessons

Promoted: the planted canary, a prose example in a model instruction is followed literally (the Step 3 `value` example), and the headless CLI that follows `PWD`. Other lessons kept here: check that "private" helpers really are private before ruling to duplicate them (D2/D6); a one-sentence skill rule can make a whole case stop at an empty slot (D36); keep run copies free of the repo's instruction files (D35); separate a validator's structure from the claim it computes (D34).
