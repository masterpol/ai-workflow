## Problem and owner decisions

A coordinator could hand each role to exactly one worker, with at most 2 workers and 3 concurrent tasks. The owner wanted several agents to split a pitch's scopes (for example implementation by opencode and claude, review by codex and opencode) with room to grow toward a swarm; LAH had tried a 3-worker file the policy rejected. The pitch was workflow-v3 pitch 4 of 5 and depended on unified-toon-config. Owner decisions on 2026-10-16: review pools use split semantics (one reviewer per scope, like implementation); `maxConcurrentWorkers` is bounded 1..16 (the pitch said "was 1..3"); one release (2.27.0) with one audit after both waves; the degenerate-review policy was left to the builder ("as you see fits"). The bet was logged without per-finding dispositions, so all 21 critique findings were acknowledged and carried into plan. A later banner on the pitch records that the TOON schema is schemaVersion 2 with Orca nested under `integrations.orca`, so references to `engines.orca` or top-level `orchestration` mean `integrations.orca.*`.

Pitch sketch (breadboard): `roles.<role>` is a string (legacy) or an array of 1..N distinct worker names; `workers` is the union of role pools; the `workers.length > 2` limit is removed and a coordinator may appear in its own pool; assignment is a deterministic split, round-robin in plan order skipping members whose preflight failed; reviewer differs from implementer when the pool allows it; concurrency is bounded by `maxConcurrentWorkers`; on a clean failure the next pool member takes the task, bounded by `maxRetriesPerTask`. Knowledge consulted at pitch time: launch authority stays with the gate, run binding verified for every pool member, each worker preflighted in its own environment, retries move on only after a proven clean failure, blocked means stop and ask.

## Upgrade note

A coordinator can list itself and several workers, and a role can be a pool (`implementation[2]: a,b`). Dispatch callers may pass `assign` (`role`, `planIndex`, `reviewOf`) instead of `vendor`. A scope whose `authorizedPaths` overlap a live attempt of another scope is refused (`authorized-paths-overlap`), so parallel scopes need disjoint paths. `orca-start` now fails if any pool member's executable is missing. A review pool that cannot differ from the implementer returns blocked with a humanAction instead of reviewing with the same vendor.

## No-gos and resolved rabbit holes

No-gos held: concurrency bounded (16 ceiling); launch authority unchanged (the gate decides on the coordinator identity before and after assignment; see [a gate spawns exactly what it probed](../../knowledge/patterns/a-gate-spawns-exactly-what-it-probed.md)); swarm behavior (dynamic spawning, agent-to-agent messaging, load scheduling) and fan-out review not built; standing workflow-tooling no-gos applied.

Resolved: the policy silently truncated pools (config accepted them, policy kept only the first member); fixed first. Round-robin versus retry and resume: assignment is a pure function and the recorded ledger owner always wins and is never reassigned; rotation only after a proven-clean failure ([retry only on proof](../../knowledge/patterns/retry-only-on-positive-proof-of-a-clean-failure.md)), and every rotated attempt passes the full gate. No ledger schema change (`vendor` and `taskKey` carry it). A coordinator in its own pool is allowed because the worker is a separate `--worker-context` process, so no authority holder changes. Reviewer independence: blocked plus humanAction. Same-file contention: refusal at `reserve`, with [orca-apply](../../../ai-framework/scripts/orca-apply.mts) `worker-overlap` as backstop (see [reconcile every worker of a wave](../../knowledge/patterns/reconcile-every-worker-of-a-wave-before-committing-any-scope.md)). Legacy single-string roles are still accepted and normalized to one-element arrays.

Pushed to plan in the pitch (and later settled): whether Orca caps concurrent terminals (probe before raising defaults past 3, which became the skipped S4), concurrent patch integration in arrival order (the plan found `orca-apply` refuses overlap instead), a ledger and evidence schema change (none was needed), and grader fixtures that hardcode `maxConcurrentWorkers: 3`.

Open at ship: concurrency above 3 live workers; case-insensitive path overlap on macOS; no in-place v2 to v3 config conversion (later resolved, see contradictions).

## Plan and exit criteria

Two waves. Wave 1 (S1 to S3) fixed the live silent-truncation defect and was shippable alone with its own full-suite gate; Wave 2 (S4 to S7) assigned. P0 precondition (satisfied 2026-10-16): vendor-model-toon S1 landed as `df9683d` so the repo's own `ai-workflow.toon` loaded; foreign dirt from agent-model-sweep (`workflow-doctor*`, `skill-defaults.test.mts`, `harnesses.md`, `model-routing.md`, one `effort` line in the example toon) was never to be staged. Plan facts verified in code: config already accepted `roles.<role>: string | string[]` and 1..16; the ledger already stores `vendor` per attempt; `dispatchScope` took the vendor from the caller and `dispatchWithRetries` re-sent it; the gate and `policy.workers.includes` run against the coordinator identity (`orca-dispatch.mts:113-125`); `orca-apply.mts:466-469` refuses overlapping worker paths; Orca 1.4.227's `worker-start --help` and top-level help document no terminal or agent cap. Size estimate: about 27 files (13 source and doc, 11 test, 3 record and mirror), about 1000 source and doc lines and 800 test lines; Wave 1 about 10 files and 450 lines, Wave 2 about 17 files and 1350 lines, with its own scope gate. The planned S7 file set included `.opencode/commands/build.md`.

Exit criteria included grep checks (no `workers.length > 2`, no string-only role filter), a determinism test over 1000 randomized calls, rotation only on retryable failures (one test per non-rotating reason: unknown-liveness, launch-failed:unproven, launch-failed stage, timeout, signal exit), the gate called once per attempt, 16 simultaneous reserves claiming and the 17th at-capacity, a ledger diff showing no schema change, evidence looked up by attempt key so a retry does not inherit another member's evidence, and a mutation proof (flip `!==` to `===` in the reviewer check). Plan risks and mitigations: per-member preflight uses the worker environment (`buildWorkerEnv`); probe distinct members once to stay inside the 4 s start budget; a new attempt id per rotation; legacy JSON keeps string roles and accepts more than 2 workers. Dispatch plan: S5 could be handed to a standard-model worker with authorized paths exactly `orca-assign.mts` and its test, with exits re-run independently; S6 stayed with the coordinator; the audit ran once after both waves (code, security, test-coverage; ux, i18n and eval skipped).

## Audit chronology

Two cycles (big-batch cap 3), must-fix open at end 0. Cycle 1 (2026-10-16): security, code and test-coverage reviewers (sonnet) and cross-pitch (haiku, read-only comparison), each on a fresh scratch copy of 106 source and test files (`review-bench.mts prepare`, see [review-bench](../../../ai-framework/scripts/review-bench.mts)) with a planted canary and no earlier findings; all canaries were caught (security: state set in `resolveAssignment`; code and test: the `live` guard in ledger `reserve`). The code and test reviewers shared one scratch tree, so the test reviewer's mid-run repair was visible to the code reviewer; both still reported the canary. Cross-file interactions reviewed: callers of `report().roles`, `dispatchWithRetries` assign passthrough, CLI assign versus `prepareOpencode`, `reserve` versus `resolveAssignment` race. Read-only was checked with a guard snapshot; changed files since were only the author's and a concurrent session's `workflow-doctor.mts`. Gap: SHA-256 of the review prompts was not recorded.

- M1 (must-fix, code): `resolveAssignment` treated a failed-then-settled attempt as the task's owner (`owner = state !== "failed"`), so rotation never moved on and `reserve` relaunched the failed vendor. Fixed: `holds()` mirrors `reserve()`'s task-owned set plus settled-with-`reportId`; a failed attempt is a tried vendor. Dispatch suite 84 pass; a mutant restoring the old predicate failed 2 tests.
- Should-fix, all fixed: S1 assigned dispatch freed OpenCode's port whenever workers had opencode instead of when the role pool did; S2 30 surviving mutants in `resolveAssignment` closed with 11 direct tests (5 spot mutants re-run and killed); S3 settled and failed overlap and legacy record without `authorizedPaths` tests; S4 direct `validatePolicy` pool tests; S5 grader cap range-checked and a failed pick no longer becomes vendor `""` (test over 0, 17, 2.5 and "4"); S6 exact retry-cap versus pool-exhaustion assertions.
- Acknowledged: path overlap is case-sensitive (a macOS default filesystem could hold `Src/` and `src/`; `orca-apply` still refuses true overlap); unreachable defensive branches in `orca-start`; a redundant `planIndex >= 0` check; `skip` has no length bound beyond the 64 KiB input cap; pools max 3 and concurrency above 3 unverified; the grader test could not run in the scratch copy (no `.project/` dataset) and was verified in the repo. Cross-pitch X1: VERSION and CHANGELOG collision with agent-model-sweep's 2.28.0, resolved by order (2.27.0 committed first); X2: vendor-model-toon's open migrator incident closed by `eb549ff`; workflow-v3-rollout must plan for no in-place v2 to v3 conversion (the reader message promises one), preflight probing every pool member, and release numbering.

Cycle 2 (code reviewer only, fresh copy, new canary: `unknown-liveness` dropped from `holds`): the canary was caught by the reviewer and by the new test `every non-failed holder keeps its vendor`. ## Knowledge and lessons

Promoted: [a schema version bump left 98 stale tests](../../knowledge/issues/a-schema-version-bump-left-98-stale-tests-and-the-migrator-on-the-old-version.md): bump the constant, emitter, refusal regex and every fixture literal in one commit and run the whole suite before calling a scope done. Related: [test skip is a follow-up, not a finish](../../knowledge/issues/test-skip-is-a-follow-up-not-a-finish.md), [a pitch can pass its own tests and break on the real file](../../knowledge/patterns/a-pitch-can-pass-its-own-tests-and-break-on-the-real-file.md), [prove a guard test with an in-memory mutant](../../knowledge/patterns/prove-a-guard-test-with-an-in-memory-mutant.md). Kept here as well: give each reviewer a fresh tree with its own planted canary and do not share a scratch tree between reviewers; a failed attempt, even later settled, is a tried vendor and not the owner; a fix that adds a state predicate needs a test for each holder state; stage by explicit path in a shared checkout.
