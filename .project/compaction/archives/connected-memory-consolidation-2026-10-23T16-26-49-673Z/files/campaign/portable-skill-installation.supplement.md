## Delivered behavior and ownership

The parent epic was split from registry-installer and skill-portability into three sequential, separately gated big-batch scopes. Each was bounded to at most 15 files/1,500 lines (the shaped sub-pitches also named one week); the plan estimated 27 unique paths, 15 new and 12 existing, including two generated Cursor mirrors. S1 estimated nine paths, S2 twelve, S3 twelve because shared paths recur. Ship reconciliation says S2 used fourteen of fifteen and S1/S3 stayed in their nine-to-twelve estimates. No application implementation or La Salle infrastructure decision belonged here.

S1 delivered add-skill, skill-registry, skill-source and skill-vendors: exact source selection and inspection, explicit scope and workflow phases, validated vendor descriptors, project/global state, ownership, staging and recoverable transactions. A skills.sh URL or owner/repository/skill identifies one skill. Bare names need a verified identity or candidates; missing, ambiguous, network and invalid-source failures are distinct and abort before target writes. Inspection returns SKILL.md instructions for review as data; downloaded setup code is not executed. Exact Git-object retrieval replaced wrapping the upstream Skills CLI after the compatibility spike, avoiding checkout, filters and hooks. Multiple upstream variants require explicit --path; selected path persists for updates. Pin the revision, preserve scripts/resources/executable modes and license metadata, then preview before approved apply.

The versioned instance registry tracks identity, source/revision, license, enabled state, phase bindings, prerequisites, original and materialized hashes, owned paths and adapters. Packages live under local .project/skills/packages; validated vendor descriptors and explicit overrides accompany the registry. Global scope has an explicitly selected user store and project link; project sync must not silently mutate global files. Scope incompatibility requires an explicit new choice. Install/update/enable/disable/remove share ownership checks; update retains phases unless changed and retains disabled state. Local changes report conflict rather than overwrite; removal verifies hashes and removes only unchanged owned files. Paths reject traversal, escaping symlinks, case collisions, reserved workflow names, duplicate/shared destination collisions and unowned overwrites. Secret-name rejection covers .env*, credentials.json and settings.local.json on fetch and every write path.

A lock, journal and verified backups serialize writes; registry is installed last. Revalidate hashes before commit; interrupted work restores a valid previous registry/package set or reports recovery conflicts. Tests covered normal exceptions and real subprocess interruption. Pending journal checks must precede namespace/registry classification. Four cohesive modules intentionally exceeded the generic eighty-line utility guideline, staying below two hundred lines each to keep ownership invariants together.

## Sync and formatting decisions

S3 delivered skill-sync ownedPaths, formatter discovery/staged formatting and reconcile. Instance registry, packages, vendors and global state stay outside bundle-sync's synced directories; only portable machinery/defaults/docs sync. Registry-owned paths are excluded from both new and removed comparison, so upstream absence cannot prune them. Two target projects retain different skill choices through apply/prune. Source .project data is never imported. Local/global content and flagged entry/config files remain protected or reviewable.

After structural apply, the same approved bundle-sync operation invokes skill-sync reconcile as a subprocess against just-written on-disk code, not the parent process's cached pre-sync require. This detects mixed schema/runtime incompatibility after partial sync. Incompatible registry state is reported without blocking the remaining structural sync; unresolved coverage blocks claiming complete skill activation. Reconcile renders only drifted owned wrappers through existing transaction/journal machinery; it never re-fetches or reformats package content. Newly registered vendors join the same preview/apply without a second blanket approval; unowned collisions or modified owned files conflict. An unregistered vendor's existing adapter is conservatively retained, not automatically deleted. Reconcile calls registry/vendors directly instead of add-skill run to avoid add-skill/skill-sync circular imports; the small duplicate render/collision logic is directly tested.

Formatting is Prettier-specific, discovered from existing project config or package.json#prettier; local node_modules/.bin precedes PATH. An unconfigured or configured-but-uninstalled formatter is treated as absent; no formatter is introduced. Only staged changed package content is formatted, never generated wrappers or the whole project. Preview formats in scratch and writes no target files. A failure aborts before any target write. sourceHash records raw upstream bytes and hash records the deterministic formatted ownership baseline, so identical reinstall is clean while real local edits remain detectable. Other formatter conventions were outside this delivery. [Dual-hash tracking](../../knowledge/patterns/dual-hash-tracking-for-transformed-content.md) and [subprocess revalidation](../../knowledge/patterns/subprocess-revalidation-against-on-disk-code.md) preserve these lessons.

## Audit findings and confidence

Cycle 1 dispatched code, security, test coverage and cross-pitch reviewers in parallel; UI/i18n/AI-prompt scopes did not apply. Zero must-fix; one should-fix corrected, another explicitly deferred. Coverage independently mapped every machine exit to tests. Cross-pitch found no real conflict with district-multisite-foundation, defaults, compaction or state; registry schema, vendor coverage and sync foundation matched downstream assumptions. Source SHIPPED listed defaults/compaction/state as queued; done-work later says all four downstream pitches including metrics shipped, a later narrative state rather than ship-time evidence for this review.

The fixed bug sliced YAML quoted frontmatter without unescaping: double-quoted descriptions retained backslash escapes and single quotes retained doubled quotes. Reproduction confirmed it; JSON.parse for double quotes and doubled-single-quote collapse fixed it with regression tests.

Deferred TOCTOU: resolveFile's ancestor lstat and later writes were not atomic. A co-resident process already able to write the project could race an ancestor into a symlink. Malicious fetched content alone did not reach it because fetched symlinks were rejected. The historical decision treated cooperative locks, not adversarial local writers, as the threat model; full inode/fstat checks across write sites were considered cross-cutting beyond appetite. This was a real residual property, not a proven absence of risk. The [standing decision](../../knowledge/decisions/workflow-tooling-pitches-share-standing-no-gos-and-design-answers.md) records that historical deferral. A separate acknowledged PID-reuse lock concern caused false locked/denial, not a bypass, and prompted no action.

The Prettier note asked whether --config disables cascading discovery. No real Prettier binary was available in the sandbox, so its own CLI semantics were not empirically verified. A spy regression proved the code always chooses --config from the trusted project root, never a same-named fetched config; no code change was needed. The [trusted-root pattern](../../knowledge/patterns/resolve-config-only-from-trusted-root.md) additionally says tool semantics should be verified rather than assumed. Do not upgrade this code-argument evidence into real-Prettier runtime proof.

Post-audit: 63/63 (62 plus formatter-provenance test), four skill modules 100% lines, aggregate branches 94.14%, functions 97.37%; doctor zero failures, validator READY/eighteen checks, graph CLEAN and collector regression 4/4. No re-dispatch was required by that record. Full line coverage does not imply full branches/functions or unverified host execution.
