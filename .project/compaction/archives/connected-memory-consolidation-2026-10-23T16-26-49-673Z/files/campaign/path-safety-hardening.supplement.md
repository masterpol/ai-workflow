## Contract and delivered behavior

The user approved a trusted-directory contract on 2026-09-27: project directories and ancestors stay under cooperating control during managed transactions. Static symlinks and observed ancestor replacement are refused, but continuous containment against a hostile ancestor rename after the final check was never implemented. It stays an unresolved stronger requirement. Scopes S1 (guarded managed and ledger writes) and P2 (shared recovery) were completed under that contract, and the user selected path safety only.

Ledger commits, archive, removal and recovery share one transaction-context constructor, target root and `.project/compaction` journal namespace (exported from pitch-compress, consumed by pitch-archive). New writes, including direct API use, refuse a pending compaction journal or a legacy installer journal and never move it. Older ledger commits used the installer context and `.project/skills`; those journals keep the installer recovery route (`add-skill recover --scope project --apply`), and new ones use `pitch-archive recover --apply`. Old and new writers use different locks, so an absent legacy journal does not prove quiescence: stop old compaction processes, including long-lived imported copies, before migration. The README records this and the trust boundary. A refused source or destination is an error, never absent. Ledger commits reusing skill-registry transactions also create and release the registry lock and journal under `.project/skills`; a pending registry transaction blocks ledger commits. The ship-readiness note adds that the validator, graph, syntax and diff checks passed and that recovery and deletion gates, ledger schema and historical records stayed protected.

## Scope and no-gos

Pitch (small batch, at most 4 files and 400 lines): resolved decisions were that co-resident write access is needed for the race yet closing it is worthwhile, and that a refused path is an error. Deterministic race simulation was pushed to plan as a risk; platform descriptor APIs and a general filesystem transaction framework were pushed to no-go. No-gos: no change to compaction retention, ledger schema or deletion approval; no change to skill source fetching or vendor mirrors; no historical record edits. Plan: S1 ran sequentially because the four files share one write contract (impact: risk medium; skill-registry also serves add-skill, skill-sync, skill-vendors, browser-runtime, skill-defaults, pitch-archive and state-snapshot). P2 (approved 2026-09-27, limited to path safety) allowed five existing files and at most 300 lines, with no implementation subagent. Collector work stayed out of scope and unshipped. No new dependency, native or Python helper.

## Audit chronology

Audit cycle 1 (2026-09-26) found the final ancestor TOCTOU, declared S1 incomplete and said the next design must select an OS-backed directory-relative primitive or explicitly narrow the threat model. The re-shape note proposed a native feasibility spike first, because an open directory descriptor can still identify a directory that was moved elsewhere. The spike showed that even a captured descriptor can follow a moved ancestor, and the user chose to narrow the contract. That "cannot ship" verdict is superseded. Cycle 1 also found the FIFO and oversized lock read (fixed: no-follow, non-blocking open, regular file, bounded read; the cycle 2 security recheck confirmed it). The native security-reviewer failed because its model was unavailable, so a default-model agent ran the checklist; no author-run check counted as independent review.

Completion audit (2026-09-27): code, security, test and cross-pitch reviewers (gpt-6-sol) hit a provider usage limit, then each completed one fresh narrower retry of eight tool calls. All four caught the scratch canary (disabled legacy refusal at the pitch-compress journal check, absent from production). Findings: D1 old and new writers use different locks (README fixed); T1 the killed-ledger test lacked source and extracted-content assertions (added; a cycle 2 test review confirmed they run after the real SIGKILL and CLI recovery); X1 the collector proposal also named README (resolved by the user choosing path safety only). The must-fix queue was empty under the approved contract. Independence meant fresh context in the same model family. Narrow coverage left comprehensive reader bounds, regex limits, registry recovery error output and broader callers unreviewed, and the collector runtime was not reviewed. Whole-tree guards saw concurrent unrelated collector, status and followup edits, so a private secret-excluding guard was used; reviewer mutation loaders with non-canonical macOS paths are not evidence. Cross-pitch: independent-rereview-catch-up must re-review these changes and rerun the compaction, archive and state suites after later fixes.

## Historical limits

Hostile concurrent directory relocation is unsolved; unsafe cleanup is refused and may keep a temp file or recovery journal in a moved original directory rather than delete through a refused path. Recovery also refuses a swapped path. The ledger symlink refusal and transaction-context mismatch followups closed with the ship; the stronger TOCTOU requirement stays open. One followup concerns excluding secret filenames from the review bench tree guard. A concurrent session committed the working tree while the work was interrupted; the implementation and test hashes still matched on resume, and authorship is not inferred from the combined diff. The re-shape note records that S1 was downhill 75% before the contract was narrowed. Compare with later work before calling any item a current defect.
