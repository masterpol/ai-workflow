# Issue: editing a canonical file alone breaks the byte-identity mirror check

## Summary

A cooldown promoted four hard rules into `.claude/agents/code-reviewer.md` and
`.claude/agents/security-reviewer.md`. Nothing told the editor that those files also exist as
byte-identical copies under `.cursor/agents/`, so `skill-defaults.test.mts`'s "every vendor mirror of
a skill or agent either points at the canonical file or is byte-identical to it" failed on the two
Cursor files, with both the canonical and the mirror carrying the new subsection.

## Symptoms

The failing assertion names the stale file directly (`.cursor/agents/code-reviewer.md is stale —
run skill-vendors.mts cursor-mirrors and refresh it`), but the failure surfaced as a wall of
`deepEqual` output from the full `scripts/*.test.mts` run, several files away from the change that
caused it. The Codex and OpenCode mirrors did not fail: they are pointer stubs that load the
canonical file, so they inherit the edit automatically.

## Root Cause

The bundle has two mirror kinds and only one of them is self-healing. Codex and OpenCode mirrors are
pointers, so they need no action. Cursor mirrors are generated byte copies, so every canonical edit
is a two-file edit — and no step in the edit path says so. `skill-vendors.mts cursor-mirrors`
reports a differing mirror but, by its own comment, writes only missing ones, so the refresh is
still a copy step by hand.

## Solution

Copied the two edited files over their `.cursor/agents/` counterparts. The test passes and reports
42 current mirrors.

## Prevention

- After editing anything under `.claude/agents/` or `.claude/skills/`, run
  `node ai-framework/scripts/skill-vendors.mts cursor-mirrors --root .` and copy every entry it
  reports under `differs`.
- A byte-identity assertion that fires far from the edit is a mirror problem until proven otherwise;
  read the assertion message before the diff it prints.
